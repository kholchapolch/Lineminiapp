Environment & Deployment Document

รายละเอียด Sandbox, UAT และ Production รวมถึง URL และ Configuration

ค่า APP_ENV ในโค้ดมีแค่ local, staging, production ชื่อธุรกิจ “UAT” ใช้ APP_ENV=staging ไม่มีค่า uat หรือ sandbox ในแอป

ภาพรวมสภาพแวดล้อม

ชื่อธุรกิจ APP_ENV โฮสต์แอปในรีโป สถานะ
Sandbox / local local http://localhost:3000 MySQL Docker พอร์ตโฮสต์ 3307 มีในรีโป (docker-compose.yml, npm run dev)
UAT / staging staging https://stglineminiapp.sony.co.th/ App Service mysonybadgestg มี workflow .github/workflows/main_mysonybadgestg.yml
Production production ไม่มี URL / App Service / workflow ในรีโปนี้ โค้ดรองรับโหมดนี้ (ปิด debug, บังคับ LIFF/DB/session) ยังไม่มี pipeline แยก
docs/uat-deployment.md และ AGENTS.md ระบุว่า push สาขา main ไป UAT ไฟล์ workflow ที่ commit ตอนนี้ trigger ที่สาขา dev และ workflow_dispatch ใช้ YAML เป็นแหล่งความจริงของทริกเกอร์จนกว่าจะแก้เอกสารหรือ workflow ให้ตรงกัน

Configuration

  • คัดลอกจาก .env.example เป็น .env.local — ห้าม commit และอย่าคัดลอกค่าตัวอย่างที่เป็น secret/LIFF จริงลงเอกสารอื่น
  • DATABASE_SSL=false สำหรับ Docker local
  • SONY_PRODUCT_API_MODE=mock
  • HTTP บน localhost ใช้ได้; config:check ไม่ใช้กับไฟล์นี้ (บังคับ HTTPS)
  • LIFF ว่างได้ในโหมด local เพื่อพรีวิวโดยไม่เข้า LINE

ที่เก็บ Configuration

  • GitHub environment secret UAT_ENV_FILE = เนื้อหาทั้งไฟล์ .env.production
  • ถูกเขียนตอน build (Windows) และก่อน deploy (Ubuntu) แล้วลบออกจาก runner
  • ไม่ถูกใส่ใน artifact กลาง
  • App Service application settings ถ้ามี จะทับค่าจากไฟล์ตอนรัน — แต่ NEXT_PUBLIC_* ต้องมีตอน npm run build
  • Publish profile: secret ชื่อยาว AZUREAPPSERVICE_PUBLISHPROFILE_… ตาม workflow — ห้ามสลับกับโปรไฟล์รีโปอื่น

คีย์ที่ npm run config:check บังคับ

DATABASE_URL, DATABASE_SSL (ต้องเปิด TLS), APP_ENV (staging หรือ production), APP_BASE_URL = NEXT_PUBLIC_APP_BASE_URL (HTTPS), ALLOWED_ORIGINS, ALLOWED_REFERRERS (HTTPS และต้องรวม origin แอป), NEXT_PUBLIC_LIFF_ID ขึ้นต้นด้วย LINE_CHANNEL_ID-, LINE_CHANNEL_ID (ตัวเลข), LINE_VERIFY_ID_TOKEN_URL, APP_SESSION_SECRET และ LOG_HASH_SECRET (≥ 32 ตัว), NEXT_PUBLIC_DEBUG_MOCK_JSON=false, SONY_PRODUCT_API_MODE (mock หรือ live), SONY_PRODUCT_API_BASE_URL, SONY_PRODUCT_API_COUNTRY_CODE (ISO สองตัวพิมพ์เล็ก), SONY_DEMO_LINE_UUID, NEXT_PUBLIC_ACCOUNT_URL, NEXT_PUBLIC_REGISTER_PRODUCT_URL

SONY_PRODUCT_API_SUBSCRIPTION_KEY จำเป็นเมื่อโหมด live โหมด mock จะเตือนในล็อก CI

รันไทม์ App Service: Windows + IIS/iisnode, Node 24 64-bit, HTTPS Only, PORT จากแพลตฟอร์ม, NODE_ENV=production ใน web.config

Production

  • ตั้ง APP_ENV=production — โหมด debug ปิดแม้มี ?debug=1
  • config:check ใช้กฎเดียวกับ UAT (HTTPS, TLS DB, mock JSON ปิด)
  • ควรใช้ seed ชุด db:seed:prod ถ้าต้องการเหรียญ/รูปแบบ dump UAT-prod
  • โดเมน LINE LIFF, APIM, MySQL, App Service ต้องกำหนดนอก Git และไม่ใส่ secret ในเอกสารนี้
อย่าชี้ Mini App production ไปที่โดเมน UAT https://stglineminiapp.sony.co.th/

สิ่งที่ห้ามทำกับ Configuration

  • Commit .env*
  • ใส่คีย์ DB, session, LINE server, APIM ใน NEXT_PUBLIC_*
  • ปิดการตรวจใบรับรอง TLS ของ MySQL
  • ใส่ http:// นำหน้า hostname ใน DATABASE_URL
