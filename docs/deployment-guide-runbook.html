Deployment Guide / Runbook

ขั้นตอน Build, Deploy, Verify, Rollback และผู้รับผิดชอบ

ใช้กับ UAT App Service mysonybadgestg Production ยังไม่มี workflow ในรีโป — ทำตามหลักการเดียวกันเมื่อมีโฮสต์แล้ว

ผู้รับผิดชอบ (RACI จากรีโป)

ไม่มี CODEOWNERS และไม่มีรายชื่อบุคคลใน Git

งาน ผู้ทำในทางปฏิบัติ หลักฐาน
Build, เทส, lint, แพ็กเกจ, deploy แอป UAT GitHub Actions งานใน environment uat main_mysonybadgestg.yml
อนุมัติ environment / เก็บ secret ผู้มีสิทธิ์ GitHub environment uat UAT_ENV_FILE, publish profile
ตั้งค่า Windows App Service (IIS, Node 24, HTTPS, Access Restrictions) เจ้าของ Azure App Service docs/uat-deployment.md
Migrate / seed MySQL ผู้ปฏิบัติการบนโฮสต์ที่เข้า Azure MySQL ได้ — ไม่ใช่ GitHub runner workflow ไม่มีขั้นตอน db:migrate
แก้โค้ดและเปิด PR ทีมพัฒนา — สาขาทริกเกอร์ตาม YAML คือ dev workflow on.push.branches
Rollback แอป ผู้มีสิทธิ์ Actions หรือ Azure Deployment Center — ไม่มีสคริปต์ในรีโป —

Build

อัตโนมัติ (UAT)

  1. Push สาขา dev หรือรัน workflow_dispatch
  2. Concurrency กลุ่ม deploy-nextjs-uat — งานใหม่ยกเลิกงานเก่าที่ยังไม่จบ
  3. Checkout + Node 24 บน windows-latest
  4. สร้าง .env.production จาก UAT_ENV_FILE
  5. npm run config:check
  6. npm ci
  7. npm run db:seed:sql:check
  8. npm test → npm run lint → npm run build
  9. แพ็กโฟลเดอร์ deploy/: .next (ตัด cache), public, server.js, web.config, package.json, package-lock.json, next.config.mjs, แล้ว npm ci --omit=dev ในนั้น
  10. อัปโหลด artifact nextjs-production-server (ไม่มี .env.production)
  11. ลบไฟล์ env บน runner ของงาน build

ด้วยมือ (เครื่องพัฒนา)

npm ci
npm test
npm run lint
npm run build

อย่า commit ผล .next ใช้ npm start (node server.js) เมื่อทดสอบโหมด production ในเครื่อง

เก็บ server.js, web.config, public/deployment-check.html และไฟล์ workflow นี้เมื่อซิงก์โค้ด เป็นรันไทม์เฉพาะ UAT Windows

Deploy

  1. งาน deploy บน ubuntu-latest รอ build สำเร็จ
  2. ดาวน์โหลด artifact ไป deploy/
  3. เขียน deploy/.env.production จาก UAT_ENV_FILE (โหมดไฟล์ 600)
  4. azure/webapps-deploy@v3 — app-name: mysonybadgestg, slot-name: Production, แพ็กเกจโฟลเดอร์ deploy
  5. ลบ env บน runner

ฐานข้อมูล: ถ้ามี schema/กฎใหม่ ให้ migrate และ seed จากเครือข่ายที่อนุญาต ก่อนหรือตามแผนที่ตกลง ไม่ได้อยู่ใน workflow

# บนโฮสต์ที่เข้า MySQL UAT ได้ — ใช้ชุดที่ตรงสภาพแวดล้อม
export DATABASE_URL='mysql://<user>:<pass>@<host>:3306/<db>?ssl=true'
export DATABASE_SSL=true
npm run db:migrate
npm run db:seed:prod
npm run db:verify:prod

จด Git SHA ที่ deploy และค่า app_config.badge_rules_version

Verify

ที่ workflow ทำอัตโนมัติ

curl พร้อม retry ไปยังโดเมน UAT:

  • https://stglineminiapp.sony.co.th/ — HTTP 2xx
  • /api/health — ตัวเนื้อมี "runtime":"nodejs"
  • /deployment-check.html — มีข้อความ Deployment smoke test passed.

ถ้าได้ 403 และหัว x-ms-forbidden-ip ให้ warning แล้วยังถือว่าขั้น verify ของ workflow ผ่าน

ที่ควรทำจาก IP ที่อนุญาต

  1. เปิด Mini App ใน LINE ตาม LIFF ของ UAT
  2. เซสชันถูกสร้างหลัง verify ID token
  3. หน้า /th/my-badges โหลดเหรียญจาก Sony live หรือ mock ตาม SONY_PRODUCT_API_MODE
  4. อย่าใช้ db:reset

Rollback

ไม่มี job rollback ใน GitHub Actions

  1. แอป: deploy แพ็กเกจ/commit ก่อนหน้าซ้ำ (GitHub workflow_dispatch บน SHA เก่า, หรือ Redeploy ใน Azure ตามประวัติถ้ามี)
  2. กฎฐานข้อมูล: restore dump ที่ถ่ายไว้ก่อน seed หรือ checkout ไฟล์ seed เก่ารวมกับ db:seed:prod — ดูแผนสำรองแยก
  3. ห้าม npm run db:reset บน UAT
  4. หลังย้อน: ตรวจ health, smoke HTML, และ SHA + badge_rules_version
การเปลี่ยน NEXT_PUBLIC_* ต้อง build ใหม่ การทับ App Service setting อย่างเดียวไม่เปลี่ยนค่าที่ฝังในคลายเอนต์แล้ว

เมื่อล้ม

อาการ ที่ดู
config:check ล้ม คีย์ขาด, HTTP ไม่ใช่ HTTPS, APP_ENV ไม่ใช่ staging/production, LIFF ไม่ตรงช่อง
db:seed:sql:check ล้ม รัน npm run db:seed:sql แล้ว commit SQL ให้ตรง seed-data.mjs
Deploy สำเร็จแต่ verify 403 Access Restrictions — ตรวจจากเครือข่ายที่อนุญาต ไม่ใช่บั๊ก Next.js
แอปขึ้นแต่เหรียญว่าง/500 ฐานยังไม่ migrate/seed, Sony API, หรือ session
