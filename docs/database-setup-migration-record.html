รายการ Script

คำสั่ง npm และไฟล์ที่เรียก
คำสั่ง (Command) ไฟล์ (Script) หน้าที่ ทำลายข้อมูลหรือไม่
npm run db:migrate scripts/db/migrate.mjs สร้างตาราง/คอลัมน์/index ตาม schema ปัจจุบัน ไม่ลบข้อมูล
npm run db:seed scripts/db/seed.mjs + seed-data.mjs upsert กฎจาก seed เริ่มต้น (path รูปใน /public) แทนที่ groups / thresholds / conditions ของกฎที่ seed
npm run db:seed:prod seed.mjs --seed ./prod/seed-data.mjs seed ชุด production/UAT (URL รูปจาก dump) เหมือน db:seed แต่คนละไฟล์ข้อมูล
npm run db:seed:all scripts/db/seed-all-rules.mjs migrate → seed → verify ติดกัน ตาม seed ที่เลือก
npm run db:seed:all:prod seed-all-rules.mjs --seed ./prod/seed-data.mjs migrate + prod seed + verify ใช้กับโฮสต์ที่เข้า Azure MySQL ได้
npm run db:verify / db:verify:prod scripts/db/verify.mjs ตรวจจำนวนแถวและมี badge_rules_version อ่านอย่างเดียว
npm run db:seed:sql scripts/db/generate-seed-sql.mjs สร้าง seed-all-rules.sql จาก seed-data.mjs ไม่แตะฐานข้อมูล
npm run db:seed:sql:check generate-seed-sql.mjs --check CI ตรวจว่า SQL ที่ commit ไม่ล้าสมัย ไม่แตะฐานข้อมูล
npm run db:reset scripts/db/reset.mjs DROP ตารางทั้งหมด แล้ว migrate + seed + verify ลบข้อมูลทั้งหมด ใช้แค่ local

ลำดับการรันที่แนะนำ

Local

docker compose up -d
export DATABASE_URL=mysql://sony:sony@127.0.0.1:3307/sony_badges
npm run db:reset

db:reset เหมาะกับเครื่องพัฒนาเพราะ DROP ตารางก่อน อย่าใช้คำสั่งนี้กับ UAT

UAT / Azure MySQL (จากโฮสต์ที่เข้าถึงได้)

  1. ตั้ง DATABASE_URL และ DATABASE_SSL=true
  2. รัน npm run db:migrate
  3. รัน npm run db:seed:all:prod หรือ migrate แล้ว import SQL ที่ generate จาก prod seed
  4. ตรวจด้วย npm run db:verify:prod
  5. บันทึก Git SHA ที่ใช้และค่า app_config.badge_rules_version
ห้ามแก้ seed-all-rules.sql ด้วยมือ แก้ที่ seed-data.mjs หรือ prod/seed-data.mjs แล้ว generate ใหม่
