Operational Handover Document

วิธีตรวจสอบระบบ Log, Monitoring และ Support Flow

แอปนี้ไม่มี Application Insights / SIEM / PagerDuty ในโค้ด การเฝ้าดูใช้แพลตฟอร์ม Azure + GitHub + ตารางปูมใน MySQL

ตรวจว่าระบบยังขึ้น

  1. จากเครือข่ายที่ Azure อนุญาต: GET https://stglineminiapp.sony.co.th/api/health ต้องได้ {"status":"ok","runtime":"nodejs"}
  2. /deployment-check.html มีข้อความ smoke test
  3. เปิด Mini App ใน LINE แล้วเข้าหน้าโฮมของ user (/th/my-badges)

ถ้าได้ 403 และหัว x-ms-forbidden-ip คือ Access Restriction ไม่ใช่ Next.js ล่ม

Log

แหล่ง มีอะไร วิธีดู
Azure App Service / iisnode stdout/stderr ของ server.js รวม console.log / console.error Log stream หรือไฟล์ล็อกของแผน App Service (สิทธิ์ Azure)
เส้นทาง API my-* บางไฟล์ console.log({ lineuuid }) ค่าดิบ — อย่าส่งสำเนาล็อกสาธารณะ กรองช่วงเวลาที่เกิดเหตุ
badge_calculation_logs เขียนเมื่อเรียก /api/customer-products เก็บ customer_line_uuid_hash (HMAC/SHA-256) ไม่ใช่ LINE ID ดิบ เส้น /api/my-* ไม่เขียนตารางนี้ 
SELECT id, customer_line_uuid_hash, source_sku_count,
       matched_sku_count, error_code, created_at
FROM badge_calculation_logs
ORDER BY created_at DESC
LIMIT 50;
GitHub Actions ล็อก build/deploy/verify ของ UAT แท็บ Actions ของรีโป
อย่าค้นล็อกด้วย LINE user ID ดิบในช่องทางที่ไม่เข้ารหัส เทียบกับ hash จาก LOG_HASH_SECRET (หรือ session secret ถ้าไม่ตั้งตัวแรก) ตาม hashLineUuid

Monitoring

  • แพลตฟอร์ม: Health check path ที่คู่มือ UAT แนะนำคือ /api/health บน App Service
  • Always On ตามแผน Azure (ถ้ารองรับ)
  • ไม่มีเมตริกธุรกิจ (จำนวนเหรียญ, อัตรา error Sony) ในแอป
  • ไม่มี alert rule ในรีโป — ตั้งที่ Azure/องค์กรถ้าต้องการ

Support Flow

  1. ผู้ใช้: แถบล่าง FAQ → https://www.sony.co.th/microsite/digital-badge/ หรือลงทะเบียนสินค้าตาม NEXT_PUBLIC_ACCOUNT_URL
  2. ถ้าเหรียญไม่ตรง: อ่าน support_message บนหน้า (debug/ลูกค้าตามที่ UI แสดง) ไม่เปิด ?debug=1 ให้ผู้ใช้บน production (APP_ENV=production ปิดอยู่แล้ว)
  3. ฝ่ายปฏิบัติการ: ตรวจ health → Log stream → ตาราง badge_calculation_logs (เฉพาะเส้น customer-products) → โหมด Sony mock/live โดยไม่พิมพ์คีย์ในแชท
  4. เซสชัน: คุกกี้ sony_line_session อายุ 1 ชั่วโมง ให้เปิด Mini App ใน LINE ใหม่ถ้าหมดอายุ
  5. ถ้ายืนยันว่ากฎผิด: อย่าแก้แถวบนฐานลวก ๆ — แก้ seed, bump badge_rules_version, สำรอง, แล้ว seed ตาม runbook
  6. ถ้ายืนยันว่าแอปพังหลัง deploy: rollback ตาม Deployment Guide ไม่ใช้ db:reset
