ภาพรวม (Overview)

Product Badge หนึ่งกฎต่อหนึ่งรุ่น · ปลดล็อกเมื่อมีอย่างน้อยหนึ่ง serial ที่จับคู่ SKU ได้ จำนวน serial ไม่ทำให้ได้เหรียญซ้ำ แต่แสดงเป็น quantity
Quest Badge เงื่อนไขหลายรุ่น · นับ unique SKU ไม่นับ serial ซ้ำของรุ่นเดียวกัน
Tier Quest สามรายการใช้ ruleType: tier Bronze / Silver / Gold จากจำนวนรุ่น unique ที่สะสมได้

ชุดปัจจุบัน: 56 Product Badge + 8 Quest (3 แบบมี tier, 5 แบบ achievement ชั้นเดียว)

ทุกกฎใน seed ตั้ง isActive ใช้งาน, activeFrom / activeTo / registrationStart / registrationEnd เป็น null จึงยังไม่มีหน้าต่างวันที่จำกัด warrantyExpiryDate จาก Sony ไม่ใช้

วิธีจับคู่ SKU และวันที่ (Matching)

  1. ใช้ modelName จาก warranty เป็น SKU ภายใน เปรียบเทียบแบบ uppercase / trim
  2. ตรงทั้งรหัส หรือรหัสกฎตามด้วย suffix ภูมิภาค (/QSYX, QSYX, SYX, /CSYX ฯลฯ)
  3. ไม่ต่อท้ายด้วยตัวอักษรรุ่นอื่น เช่น SEL70200GM ไม่ตรงกฎ SEL70200G
  4. ถ้ามีหน้าต่างลงทะเบียน ใช้เฉพาะ registrationDate ที่อยู่ในช่วง (รวมวันเริ่มและวันสิ้นสุด ตาม UTC วันที่)

ประเภทเงื่อนไข (matchType):

  • any — นับ unique SKU ในรายการ สูงสุดเท่า requiredCount ของเงื่อนไขนั้น (มักเป็น 1)
  • all — ต้องครบทุกรุ่นในรายการ เครื่องคำนวณใช้ requiredCount = ความยาวรายการ SKU
  • min_count — นับ unique SKU ในรายการ เทียบกับ requiredCount

ถ้ากฎมีหลายเงื่อนไข (เช่น Trinity Master) ค่า matchedCount คือผลรวมของแต่ละเงื่อนไข สินค้าชิ้นเดียวถูกนับในเงื่อนไขที่ตรงได้ แต่ไม่นับสองครั้งใน Map แสดงผล

สถานะแต่ละชั้นบน Mini App

  • achieved — matchedCount ≥ requiredCount ของชั้นนั้น earnedAt = วันที่ลงทะเบียนของรุ่นที่ทำให้ถึงเกณฑ์ (เรียงวันที่ แล้วหยิบชิ้นที่ลำดับเท่าเกณฑ์)
  • in-progress — ชั้นถัดจากชั้นสูงสุดที่ได้แล้ว หรือชั้นแรกเมื่อมี matchedCount > 0 แต่ยังไม่ถึง Bronze

highestEarnedTier คือชั้น achieved ที่สูงสุด หน้า my-badges โชว์ภารกิจล่าสุดจากวันที่ของชั้นนี้

หน่วยที่นับ (What is counted)

Warranty row หนึ่งแถวจาก Sony = หนึ่ง serial + modelName + วันที่ลงทะเบียน
Product Model (แถวสินค้า) ใช้บน Product Badge · นับทุก serial ที่จับคู่รุ่นนั้นได้
Unique Model ใช้บน Quest / Threshold · นับรหัสรุ่นที่ normalize แล้วไม่ซ้ำ

กุญแจ unique คือ normalizeSku(modelName) = ตัดช่องว่างหัวท้ายแล้วทำเป็นตัวพิมพ์ใหญ่ LENS-A กับ lens-a คือรุ่นเดียวกัน

ไม่ยุบ suffix ภูมิภาคเข้ากุญแจเดียวกัน SEL35F14GM กับ SEL35F14GM/QSYX เป็นสอง unique model ใน Quest แบบ min_count ทั้งที่ทั้งคู่จับคู่กฎ SEL35F14GM ได้

การนับ Product Model

สำหรับกฎ badgeType: product Mini App ไม่ใช้ calculateRuleMatch เพื่อปลดล็อก กรองทุกแถว warranty ที่

  1. matchesEligibleSku(sku, rule.skus) เป็นจริง
  2. วันที่ลงทะเบียนอยู่ในหน้าต่างของกฎ (ถ้ามี)

แล้วเรียงวันที่จากเก่าไปใหม่

ฟิลด์ที่ได้
ฟิลด์ สูตร
quantity จำนวนแถวที่ผ่านตัวกรอง (นับ serial ซ้ำได้)
registrations รายการ serial + วันที่ทั้งหมด
earnedAt วันที่ของแถวแรกหลังเรียง (ลงทะเบียนเก่าสุด)
สถานะ unlocked เมื่อ quantity ≥ 1 ไม่เช่นนั้น locked

เกณฑ์ในฐานข้อมูลของ Product Badge คือ requiredCount: 1 แต่ UI ไม่แสดง progress แบบ Quest

การนับ Unique Model

ฟังก์ชัน uniqueEligibleProducts เดินรายการสินค้าตามลำดับที่ Sony ส่งมา เก็บแถวแรกต่อหนึ่งกุญแจ normalizeSku ที่

  • จับคู่รายการ SKU ของเงื่อนไขหรือของกฎได้
  • ผ่านหน้าต่างวันที่ลงทะเบียน

ความยาวของ Map นี้คือจำนวน unique ที่เข้าเงื่อนไขนั้น

รวมหลายเงื่อนไข (calculateRuleMatch)

  1. แต่ละเงื่อนไขสร้างชุด unique ของตัวเองจาก condition.sonySkus
  2. เรียงชุดนั้นตาม registeredAt
  3. เพดานการนับ: all ใช้ความยาวรายการ SKU · any / min_count ใช้ requiredCount ของเงื่อนไข
  4. matchedCount += min(จำนวน unique ของเงื่อนไข, เพดาน)
  5. เก็บสินค้าที่ถูกนับจริงไว้ใน Map รวม (เช่น any ที่เพดาน 1 เก็บแค่รุ่นแรกตามวันที่)

Trinity Master จึงนับได้สูงสุด 3 แม้ลูกค้าจะมีทั้ง GM และ GM II ในทุกครอบครัว

Threshold

แต่ละกฎมีหนึ่งแถวขึ้นไปใน badge_rule_thresholds เรียงด้วย requiredCount แล้วตาม sortOrder

สูตรเทียบเกณฑ์
ค่า ความหมาย
เกณฑ์ที่ถึงแล้ว ทุก threshold ที่ matchedCount ≥ requiredCount
ชั้นที่แสดงเป็น earned (engine) threshold ที่ถึงแล้วซึ่ง requiredCount สูงสุด
เกณฑ์ถัดไป threshold แรกที่ matchedCount < requiredCount
remainingCount max(requiredCount ของเกณฑ์ที่ใช้อ้างอิง − matchedCount, 0)
progress min(100, round(matchedCount / requiredCount × 100)) ถ้า requiredCount ≤ 0 ให้ 100

บน Mini App แต่ละชั้น Quest แสดง matchedCount ที่ตัดเพดานที่เกณฑ์ชั้นนั้น (min(matchedCount, requiredCount)) ดังนั้นชั้น Bronze ที่เกณฑ์ 2 เมื่อมี 4 รุ่นจะโชว์ความคืบหน้า 2/2 ไม่ใช่ 4/2

Tier Upgrade

ไม่มีตารางประวัติชั้นแยก ทุกครั้งที่โหลดหน้าจะคำนวณใหม่จากรายการ warranty ปัจจุบัน

  1. คำนวณ matchedCount ของ Quest
  2. ชั้นใดที่ matchedCount ≥ requiredCount เป็น achieved พร้อมกันทั้งหมด (Bronze ไม่หายเมื่อได้ Gold)
  3. ชั้นถัดจากชั้นสูงสุดที่ได้แล้วเป็น in-progress ถ้ายังมีเกณฑ์ที่สูงกว่า
  4. ถ้ายังไม่ได้แม้ Bronze แต่ matchedCount > 0 ชั้นแรกเป็น in-progress
  5. วันที่ได้แต่ละชั้น: เรียงสินค้าทั้งก้อนตามวันที่ แล้วค่อยใส่ทีละชิ้น จน calculateRuleMatch ของ prefix นั้น ≥ เกณฑ์ชั้น วันที่ของชิ้นที่ทำให้ถึงเกณฑ์คือ earnedAt

ไม่มี “downgrade event” ถ้า Sony เลิกรายการรุ่นในรอบถัดไป matchedCount จะลด และชั้นที่เคยได้ใน UI อาจกลับเป็น locked / in-progress เพราะไม่มี persist ชั้นที่เคยถึง

Quest แบบ ruleType: achievement มี threshold เดียว ไม่มีเส้นทางเลื่อน Bronze→Silver→Gold

รหัสฐานเดียวกันแต่ suffix แคตตาล็อกต่างกัน จับคู่ Product Badge ของรหัสฐานได้ทั้งคู่ Quest min_count นับเป็นสอง unique

Hash แคชของ /api/customer-products (skuHash) คือ SHA-256 ของชุด unique normalizeSku ทั้งก้อนที่ถือครอง ไม่ใช่เฉพาะรุ่นในกฎ Serial ซ้ำของรุ่นเดียวกันไม่เปลี่ยน hash

DT-01 · จับคู่รหัสรุ่น (SKU match)

Input: modelName จาก warranty (ใช้เป็น sku ภายใน) และรายการรหัสในกฎ

ผล: แถวนี้เข้าเงื่อนไขเหรียญหรือไม่
ID Input Condition ผลลัพธ์ที่ระบบต้องออก
SKU-01 sel2450g vs กฎ SEL2450G uppercase + trim แล้วเท่ากัน จับคู่ได้ (match)
SKU-02 SEL70200GM/QSYX vs SEL70200GM ส่วนที่เหลือเป็น suffix ภูมิภาคที่รู้จัก จับคู่ได้
SKU-03 SEL70200GM2QSYX vs SEL70200GM2 suffix QSYX ติดรหัสโดยไม่มี / จับคู่ได้
SKU-04 SEL70200GM/QSYX vs SEL70200G ส่วนที่เหลือขึ้นต้นด้วย M ไม่ใช่ suffix ไม่จับคู่
SKU-05 SEL1635GM2 vs SEL2450G รหัสคนละรุ่น ไม่จับคู่
SKU-06 รุ่นที่ไม่มีในกฎใดเลย ไม่ตรง Product และไม่ตรง Quest SKU ไม่ปลดล็อกเหรียญ · ไม่เพิ่ม unique ของ Quest (ยังอยู่ในรายการถือครองดิบ)

DT-02 · Product Badge

Input: รายการ warranty ของลูกค้า + กฎ badgeType: product (เกณฑ์ requiredCount = 1)

ID Input Condition ผลลัพธ์ที่ระบบต้องออก
PB-01 0 serial ที่จับคู่รุ่นนี้ — Mini App: locked · quantity = 0 · earnedAt = null
PB-02 1 serial ที่จับคู่ได้ อยู่ในหน้าต่างลงทะเบียน (ถ้ามี) unlocked · quantity = 1 · ใช้รูป achieved · earnedAt = วันลงทะเบียนนั้น
PB-03 หลาย serial ของรุ่นเดียวกัน ทุกแถวจับคู่รหัสเดียวกัน ยังเป็นเหรียญเดียว · quantity = n · เก็บทุก serial · earnedAt = วันเก่าสุด
PB-04 ถือครอง SEL1224GM อย่างเดียว ไม่มีกฎ product ของรหัสนี้ ไม่มีแถว Product Badge · อาจนับใน Wide Architect
PB-05 กฎ isActive = false หรือเลย activeTo กฎไม่ผ่าน isRuleActive ไม่แสดงเหรียญนี้ในประสบการณ์ Mini App

DT-03 · Quest · นับ unique ตาม matchType

Input: unique รุ่นที่จับคู่รายการ SKU ของเงื่อนไขได้ หลังตัดสินค้าซ้ำตาม normalizeSku

ID Input Condition ผลลัพธ์ที่ระบบต้องออก
Q-01 any, requiredCount = 1, พูล 2+ รุ่น มีอย่างน้อย 1 unique ในพูล เงื่อนไขนี้ให้ matchedCount += 1 (เพดาน 1 แม้ถือหลายรุ่นในพูล)
Q-02 all, รายการ SKU ความยาว N unique ที่จับคู่ได้ = N เงื่อนไขครบ · บวก N เข้า matched รวม
Q-03 all, รายการความยาว N unique < N บวกจำนวนที่มีจริง · ยังไม่ถึงเกณฑ์ชั้น achievement
Q-04 min_count, เป้า K จากพูล unique = U บวก min(U, K ของเงื่อนไข) ชั้น Bronze/Silver เทียบ U กับเกณฑ์ชั้น ไม่ใช่กับ K เสมอ (K ใน seed ของ tier = เป้า Gold)
Q-05 Trinity Master · 3 เงื่อนไข any/1 ครบ 3 ครอบครัว (GM หรือ GM II อย่างใดอย่างหนึ่งต่อครอบครัว) matchedCount = 3 · achievement earned / ชั้นเดียว achieved
Q-06 Trinity Master มีทั้ง SEL1635GM และ SEL1635GM2 เท่านั้น matchedCount = 1 · ยังไม่ earned
Q-07 All Rounder · min_count 3 จาก 4 ถือ 3 รุ่นในพูล earned (achievement)
Q-08 F2 Master / Trinity Junior · all ขาดอย่างน้อย 1 รุ่นบังคับ ไม่ earned · Mini App ชั้นเดียว locked หรือ in-progress ตามจำนวน

DT-04 · Threshold และสถานะชั้น (Tier)

Input: matchedCount ของ Quest และรายการ threshold เรียงตาม requiredCount

ID Input Condition ผลลัพธ์ที่ระบบต้องออก
T-01 matchedCount = 0 — Engine: no-badge · Mini App ทุกชั้น locked · highestEarnedTier = null
T-02 0 < matchedCount < เกณฑ์ชั้นแรก เช่น Portrait unique = 1, Bronze = 2 Engine: locked · Mini App ชั้นแรก in-progress ที่เหลือ locked
T-03 matchedCount ≥ Bronze และ < Silver เช่น Portrait = 2 Bronze achieved · Silver in-progress · Gold locked · engine earned ที่ระดับ bronze
T-04 matchedCount ≥ Gold เช่น Portrait ≥ 4, Wide ≥ 5, Visionary ≥ 4 Bronze+Silver+Gold ทั้งหมด achieved · ไม่มีชั้น in-progress
T-05 แสดง progress รายชั้น matchedCount เกินเกณฑ์ชั้นนั้น UI ใช้ min(matchedCount, requiredCount) ของชั้นนั้น
T-06 Quest achievement ชั้นเดียว matchedCount ≥ requiredCount ของ threshold เดียว ชั้นนั้น achieved · ไม่มีเส้นทางเลื่อนโลหะ
T-07 รอบถัดไป Sony ส่งรุ่นน้อยลง matchedCount ต่ำกว่าเกณฑ์ที่เคยถึง คำนวณใหม่ตามข้อมูลปัจจุบัน ไม่ persist ชั้นเก่า

DT-05 · หน้าต่างวันที่ (Date windows)

ชุด seed ปัจจุบันเป็น null ทั้งช่วงแสดงผลและช่วงลงทะเบียน แถวด้านล่างคือพฤติกรรมเมื่อมีการตั้งค่าในฐานข้อมูล

ID Input Condition ผลลัพธ์ที่ระบบต้องออก
D-01 activeFrom / activeTo = null, isActive = true now เท่าใดก็ได้ กฎถูกใช้คำนวณ
D-02 now อยู่ก่อน activeFrom หรือหลัง activeTo หรือ isActive = false ซ่อนกฎทั้งก้อน (รายการเหรียญว่างสำหรับกฎนั้น)
D-03 สินค้าลงทะเบียนใน registrationStart–End now เลยช่วงลงทะเบียน แต่ยังอยู่ในช่วงแสดงผล ยังนับสินค้าชิ้นนั้น และยังถือเหรียญที่ได้แล้ว
D-04 สินค้าลงทะเบียนหลัง registrationEnd — ไม่นับชิ้นนั้นในกฎนี้
D-05 registeredAt ว่างหรือ parse เป็นวันที่ไม่ได้ isWithinDateWindow ไม่นับแถวนี้
D-06 warrantyExpiryDate ใดๆ — ไม่มีผลต่อการปลดล็อก

DT-06 · สินค้าซ้ำ (Duplicates)

ID Input Condition ผลลัพธ์ที่ระบบต้องออก
DUP-01 สอง serial รหัสเดียวกัน (ตัวพิมพ์ต่างกันถือว่ารุ่นเดียว) — Product: quantity 2 · Quest: unique 1 ไม่เลื่อนชั้นจาก serial ที่สอง
DUP-02 GM และ GM II ในครอบครัว Trinity เดียวกัน เงื่อนไข any เพดาน 1 สอง Product Badge · Quest ครอบครัวนั้นนับ 1
DUP-03 SEL35F14GM และ SEL35F14GM/QSYX กุญแจ unique ไม่ยุบ suffix Product ของรหัสฐาน: quantity รวมทั้งคู่ · Quest min_count: นับ 2 unique

DT-07 · Sony warranty API (โหมด live)

Input: HTTP status + JSON body ของ QueryWarrantyMySonyByLine

ID Input Condition ผลลัพธ์ที่ระบบต้องออก
S-01 HTTP 200, prodDetails เป็นอาร์เรย์ ทุกแถวมี modelName และ registrationDate เป็นสตริง ได้รายการสินค้า · serial ว่างได้ · ละ warrantyExpiryDate
S-02 HTTP 200, prodDetails: [] พบลูกค้าแต่ไม่มีสินค้า คำนวณเหรียญทั้งหมด locked / no-badge ไม่ใช่ 404
S-03 HTTP 404 — โยน CUSTOMER_NOT_FOUND
S-04 HTTP อื่นที่ไม่ใช่ 2xx รวม 401/403/5xx โยน SONY_PRODUCT_API_ERROR
S-05 HTTP 200 แต่ไม่มีอาร์เรย์ prodDetails และไม่ใช่รูปแบบ customer/products สำรอง SONY_PRODUCT_API_ERROR
S-06 แถวใดแถวหนึ่งขาด modelName หรือ registrationDate — ทิ้งทั้ง payload เป็น SONY_PRODUCT_API_ERROR
S-07 ไม่มี subscription key / fetch ล้ม ไม่มีรหัส TIMEOUT ในแอป SONY_PRODUCT_API_ERROR หรือ UNKNOWN_ERROR

DT-08 · ผลลัพธ์ HTTP ตามพื้นผิว API

ID Input Condition ผลลัพธ์ที่ระบบต้องออก
A-01 GET /api/customer-products ไม่มีเซสชันที่ตรวจแล้ว 401 UNAUTHORIZED
A-02 customer-products Sony 404 404 CUSTOMER_NOT_FOUND + เขียน calculation log
A-03 customer-products Sony/DB error อื่น 500 รหัสปลอดภัย + เขียน log error

A-08 /api/my-products/[id] หรือ mission detail รหัสไม่อยู่ในกฎ หรือยังไม่ปลดล็อก (product detail) 404 NOT_FOUND

Mini App /api/my-* ไม่ตรวจคุกกี้เซสชัน ใครส่ง lineuuid ได้ถือเป็น input ของการคำนวณ
