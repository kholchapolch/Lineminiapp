ภาพรวมสภาพแวดล้อม

ชื่อธุรกิจ APP_ENV โฮสต์แอปในรีโป สถานะ
Sandbox / local local http://localhost:3000 MySQL Docker พอร์ตโฮสต์ 3307 มีในรีโป (docker-compose.yml, npm run dev)
UAT / staging staging https://stglineminiapp.sony.co.th/ App Service mysonybadgestg มี workflow .github/workflows/main_mysonybadgestg.yml
Production production ไม่มี URL / App Service / workflow ในรีโปนี้ โค้ดรองรับโหมดนี้ (ปิด debug, บังคับ LIFF/DB/session) ยังไม่มี pipeline แยก
docs/uat-deployment.md และ AGENTS.md ระบุว่า push สาขา main ไป UAT ไฟล์ workflow ที่ commit ตอนนี้ trigger ที่สาขา dev และ workflow_dispatch ใช้ YAML เป็นแหล่งความจริงของทริกเกอร์จนกว่าจะแก้เอกสารหรือ workflow ให้ตรงกัน

Sandbox (local)

URL

จุดเข้า URL
แอป Next.js http://localhost:3000
สุขภาพ (ถ้าเซิร์ฟเวอร์รัน) http://localhost:3000/api/health

Configuration

  • คัดลอกจาก .env.example เป็น .env.local — ห้าม commit และอย่าคัดลอกค่าตัวอย่างที่เป็น secret/LIFF จริงลงเอกสารอื่น
  • DATABASE_SSL=false สำหรับ Docker local
  • SONY_PRODUCT_API_MODE=mock
  • HTTP บน localhost ใช้ได้; config:check ไม่ใช้กับไฟล์นี้ (บังคับ HTTPS)
  • LIFF ว่างได้ในโหมด local เพื่อพรีวิวโดยไม่เข้า LINE

UAT (staging)

URL สาธารณะที่ระบุใน workflow / คู่มือ UAT
บทบาท URL หรือชื่อ
โดเมนแอป https://stglineminiapp.sony.co.th/
Health https://stglineminiapp.sony.co.th/api/health → {"status":"ok","runtime":"nodejs"}
Smoke ไฟล์สถิต https://stglineminiapp.sony.co.th/deployment-check.html
Azure App Service mysonybadgestg สล็อตชื่อ Production (สล็อตดีพลอย ไม่ใช่ APP_ENV)
GitHub environment uat

Azure Access Restrictions อาจตอบ 403 พร้อมหัว x-ms-forbidden-ip ถ้า IP ผู้เรียกไม่อยู่ใน allowlist workflow ถือว่าเป็นคำเตือน ไม่ใช่แอปพัง

ที่เก็บ Configuration

  • GitHub environment secret UAT_ENV_FILE = เนื้อหาทั้งไฟล์ .env.production
  • ถูกเขียนตอน build (Windows) และก่อน deploy (Ubuntu) แล้วลบออกจาก runner
  • ไม่ถูกใส่ใน artifact กลาง
  • App Service application settings ถ้ามี จะทับค่าจากไฟล์ตอนรัน — แต่ NEXT_PUBLIC_* ต้องมีตอน npm run build
  • Publish profile: secret ชื่อยาว AZUREAPPSERVICE_PUBLISHPROFILE_… ตาม workflow — ห้ามสลับกับโปรไฟล์รีโปอื่น

คีย์ที่ npm run config:check บังคับ

DATABASE_URL, DATABASE_SSL (ต้องเปิด TLS), APP_ENV (staging หรือ production), APP_BASE_URL = NEXT_PUBLIC_APP_BASE_URL (HTTPS), ALLOWED_ORIGINS, ALLOWED_REFERRERS (HTTPS และต้องรวม origin แอป), NEXT_PUBLIC_LIFF_ID ขึ้นต้นด้วย LINE_CHANNEL_ID-, LINE_CHANNEL_ID (ตัวเลข), LINE_VERIFY_ID_TOKEN_URL, APP_SESSION_SECRET และ LOG_HASH_SECRET (≥ 32 ตัว), NEXT_PUBLIC_DEBUG_MOCK_JSON=false, SONY_PRODUCT_API_MODE (mock หรือ live), SONY_PRODUCT_API_BASE_URL, SONY_PRODUCT_API_COUNTRY_CODE (ISO สองตัวพิมพ์เล็ก), SONY_DEMO_LINE_UUID, NEXT_PUBLIC_ACCOUNT_URL, NEXT_PUBLIC_REGISTER_PRODUCT_URL

SONY_PRODUCT_API_SUBSCRIPTION_KEY จำเป็นเมื่อโหมด live โหมด mock จะเตือนในล็อก CI

รันไทม์ App Service: Windows + IIS/iisnode, Node 24 64-bit, HTTPS Only, PORT จากแพลตฟอร์ม, NODE_ENV=production ใน web.config

Production

  • ตั้ง APP_ENV=production — โหมด debug ปิดแม้มี ?debug=1
  • config:check ใช้กฎเดียวกับ UAT (HTTPS, TLS DB, mock JSON ปิด)
  • ควรใช้ seed ชุด db:seed:prod ถ้าต้องการเหรียญ/รูปแบบ dump UAT-prod
  • โดเมน LINE LIFF, APIM, MySQL, App Service ต้องกำหนดนอก Git และไม่ใส่ secret ในเอกสารนี้
อย่าชี้ Mini App production ไปที่โดเมน UAT https://stglineminiapp.sony.co.th/

สิ่งที่ห้ามทำกับ Configuration

  • Commit .env*
  • ใส่คีย์ DB, session, LINE server, APIM ใน NEXT_PUBLIC_*
  • ปิดการตรวจใบรับรอง TLS ของ MySQL
  • ใส่ http:// นำหน้า hostname ใน DATABASE_URL

Environment Variable

เครื่องหมาย: Public = ฝังในคลายเอนต์ · Server = เซิร์ฟเวอร์เท่านั้น · Secret = ห้ามใส่เอกสาร/คอมมิต
ตัวแปร ชั้น ตรวจอะไร (ไม่ใส่ค่าจริง)
APP_ENV Server UAT ใช้ staging · โปรดักชันใช้ production · ห้าม uat
APP_BASE_URL / NEXT_PUBLIC_APP_BASE_URL Server + Public HTTPS เดียวกันทั้งคู่ และอยู่ในรายการ origin/referrer
DATABASE_URL Secret โปรโตคอล mysql: ไม่มี prefix http ที่โฮสต์
DATABASE_SSL Server deploy ต้องเปิด TLS (true / ?ssl=true)
ALLOWED_ORIGINS / ALLOWED_REFERRERS Server รายการ HTTPS คั่นด้วยจุลภาค รวม origin ของแอป — ใช้กับ /entry
NEXT_PUBLIC_LIFF_ID Public ขึ้นต้นด้วย {LINE_CHANNEL_ID}- ห้ามวางค่าเต็มในวิกิสาธารณะถ้าถือเป็นรหัสช่อง
LINE_CHANNEL_ID Server ตัวเลขเท่านั้น ใช้ verify ID token
LINE_VERIFY_ID_TOKEN_URL Server ค่าเริ่มต้นในโค้ด: https://api.line.me/oauth2/v2.1/verify
APP_SESSION_SECRET / LOG_HASH_SECRET Secret ยาวอย่างน้อย 32 ตัว · HMAC คุกกี้และ hash ในปูม
NEXT_PUBLIC_DEBUG_MOCK_JSON Public deploy ต้องเป็น false
SONY_PRODUCT_API_MODE Server mock หรือ live
SONY_PRODUCT_API_BASE_URL Server URL เต็มรวม path เมื่อโหมด live
SONY_PRODUCT_API_SUBSCRIPTION_KEY Secret จำเป็นเมื่อ live · ส่งเป็นหัว Ocp-Apim-Subscription-Key
SONY_PRODUCT_API_COUNTRY_CODE Server ISO สองตัวพิมพ์เล็ก ค่าเริ่มต้นในโค้ด th
SONY_DEMO_LINE_UUID Server ตัวระบุ mock ในเครื่อง ไม่ใช้แทนเซสชันที่หายบน staging
NEXT_PUBLIC_ACCOUNT_URL Public HTTPS · ลิงก์ลงทะเบียนที่แถบล่าง
NEXT_PUBLIC_REGISTER_PRODUCT_URL Public HTTPS · ใช้ตอนภารกิจยังไม่ครบ (ไม่ต่อ query callback)
ห้ามใส่ NEXT_PUBLIC_* ให้กับรหัสผ่าน, subscription key, session secret ค่า Public ถูกฝังตอน npm run build

LIFF

  • ใน LINE Developers: สร้าง LIFF (Mini App) ให้ liffId ตรง NEXT_PUBLIC_LIFF_ID
  • Endpoint URL ในคอนโซล LINE ต้องเป็น HTTPS ของแอป เช่น https://<host>/th/my-badges (ต้องตรงโดเมนที่อนุญาต)
  • ขนาด/ประเภทตามคอนโซล LINE — โค้ดบังคับ liff.isInClient() ก่อนสร้างเซสชัน
  • Channel ID ของ Login ต้องเป็นชุดเดียวกับ LINE_CHANNEL_ID

Callback URL

ชนิด มีในแอปหรือไม่ หมายเหตุ
LINE OAuth redirect_uri ของเว็บ Login ไม่มี route รับ code ใช้ LIFF ID token → POST /api/line-session
แลกเซสชันแอป POST https://<host>/api/line-session บอดี้ { "idToken": "…" } ตั้งคุกกี้ HttpOnly
LINE Mini App deep link (สร้างในโค้ดแต่ยังไม่ส่งออก) รูปแบบ https://miniapp.line.me/{liffId}/th/my-missions/{missionId} buildRegisterProductUrl คอมเมนต์การใส่ callback จึงไม่ต่อเข้า URL ลงทะเบียนสินค้า
Facebook Login / OAuth ไม่มี —

ผู้รับผิดชอบ (RACI จากรีโป)

ไม่มี CODEOWNERS และไม่มีรายชื่อบุคคลใน Git

งาน ผู้ทำในทางปฏิบัติ หลักฐาน
Build, เทส, lint, แพ็กเกจ, deploy แอป UAT GitHub Actions งานใน environment uat main_mysonybadgestg.yml
อนุมัติ environment / เก็บ secret ผู้มีสิทธิ์ GitHub environment uat UAT_ENV_FILE, publish profile
ตั้งค่า Windows App Service (IIS, Node 24, HTTPS, Access Restrictions) เจ้าของ Azure App Service docs/uat-deployment.md
Migrate / seed MySQL ผู้ปฏิบัติการบนโฮสต์ที่เข้า Azure MySQL ได้ — ไม่ใช่ GitHub runner workflow ไม่มีขั้นตอน db:migrate
แก้โค้ดและเปิด PR ทีมพัฒนา — สาขาทริกเกอร์ตาม YAML คือ dev workflow on.push.branches
Rollback แอป ผู้มีสิทธิ์ Actions หรือ Azure Deployment Center — ไม่มีสคริปต์ในรีโป —

Build

อัตโนมัติ (UAT)

  1. Push สาขา dev หรือรัน workflow_dispatch
  2. Concurrency กลุ่ม deploy-nextjs-uat — งานใหม่ยกเลิกงานเก่าที่ยังไม่จบ
  3. Checkout + Node 24 บน windows-latest
  4. สร้าง .env.production จาก UAT_ENV_FILE
  5. npm run config:check
  6. npm ci
  7. npm run db:seed:sql:check
  8. npm test → npm run lint → npm run build
  9. แพ็กโฟลเดอร์ deploy/: .next (ตัด cache), public, server.js, web.config, package.json, package-lock.json, next.config.mjs, แล้ว npm ci --omit=dev ในนั้น
  10. อัปโหลด artifact nextjs-production-server (ไม่มี .env.production)
  11. ลบไฟล์ env บน runner ของงาน build

ด้วยมือ (เครื่องพัฒนา)

npm ci
npm test
npm run lint
npm run build

อย่า commit ผล .next ใช้ npm start (node server.js) เมื่อทดสอบโหมด production ในเครื่อง

เก็บ server.js, web.config, public/deployment-check.html และไฟล์ workflow นี้เมื่อซิงก์โค้ด เป็นรันไทม์เฉพาะ UAT Windows

Deploy

  1. งาน deploy บน ubuntu-latest รอ build สำเร็จ
  2. ดาวน์โหลด artifact ไป deploy/
  3. เขียน deploy/.env.production จาก UAT_ENV_FILE (โหมดไฟล์ 600)
  4. azure/webapps-deploy@v3 — app-name: mysonybadgestg, slot-name: Production, แพ็กเกจโฟลเดอร์ deploy
  5. ลบ env บน runner

ฐานข้อมูล: ถ้ามี schema/กฎใหม่ ให้ migrate และ seed จากเครือข่ายที่อนุญาต ก่อนหรือตามแผนที่ตกลง ไม่ได้อยู่ใน workflow

# บนโฮสต์ที่เข้า MySQL UAT ได้ — ใช้ชุดที่ตรงสภาพแวดล้อม
export DATABASE_URL='mysql://<user>:<pass>@<host>:3306/<db>?ssl=true'
export DATABASE_SSL=true
npm run db:migrate
npm run db:seed:prod
npm run db:verify:prod

จด Git SHA ที่ deploy และค่า app_config.badge_rules_version

Verify

ที่ workflow ทำอัตโนมัติ

curl พร้อม retry ไปยังโดเมน UAT:

  • https://stglineminiapp.sony.co.th/ — HTTP 2xx
  • /api/health — ตัวเนื้อมี "runtime":"nodejs"
  • /deployment-check.html — มีข้อความ Deployment smoke test passed.

ถ้าได้ 403 และหัว x-ms-forbidden-ip ให้ warning แล้วยังถือว่าขั้น verify ของ workflow ผ่าน

ที่ควรทำจาก IP ที่อนุญาต

  1. เปิด Mini App ใน LINE ตาม LIFF ของ UAT
  2. เซสชันถูกสร้างหลัง verify ID token
  3. หน้า /th/my-badges โหลดเหรียญจาก Sony live หรือ mock ตาม SONY_PRODUCT_API_MODE
  4. อย่าใช้ db:reset

Rollback

ไม่มี job rollback ใน GitHub Actions

  1. แอป: deploy แพ็กเกจ/commit ก่อนหน้าซ้ำ (GitHub workflow_dispatch บน SHA เก่า, หรือ Redeploy ใน Azure ตามประวัติถ้ามี)
  2. กฎฐานข้อมูล: restore dump ที่ถ่ายไว้ก่อน seed หรือ checkout ไฟล์ seed เก่ารวมกับ db:seed:prod — ดูแผนสำรองแยก
  3. ห้าม npm run db:reset บน UAT
  4. หลังย้อน: ตรวจ health, smoke HTML, และ SHA + badge_rules_version
การเปลี่ยน NEXT_PUBLIC_* ต้อง build ใหม่ การทับ App Service setting อย่างเดียวไม่เปลี่ยนค่าที่ฝังในคลายเอนต์แล้ว

เมื่อล้ม

อาการ ที่ดู
config:check ล้ม คีย์ขาด, HTTP ไม่ใช่ HTTPS, APP_ENV ไม่ใช่ staging/production, LIFF ไม่ตรงช่อง
db:seed:sql:check ล้ม รัน npm run db:seed:sql แล้ว commit SQL ให้ตรง seed-data.mjs
Deploy สำเร็จแต่ verify 403 Access Restrictions — ตรวจจากเครือข่ายที่อนุญาต ไม่ใช่บั๊ก Next.js
แอปขึ้นแต่เหรียญว่าง/500 ฐานยังไม่ migrate/seed, Sony API, หรือ session

Log

แหล่ง มีอะไร วิธีดู
Azure App Service / iisnode stdout/stderr ของ server.js รวม console.log / console.error Log stream หรือไฟล์ล็อกของแผน App Service (สิทธิ์ Azure)
เส้นทาง API my-* บางไฟล์ console.log({ lineuuid }) ค่าดิบ — อย่าส่งสำเนาล็อกสาธารณะ กรองช่วงเวลาที่เกิดเหตุ
badge_calculation_logs เขียนเมื่อเรียก /api/customer-products เก็บ customer_line_uuid_hash (HMAC/SHA-256) ไม่ใช่ LINE ID ดิบ เส้น /api/my-* ไม่เขียนตารางนี้ 
SELECT id, customer_line_uuid_hash, source_sku_count,
       matched_sku_count, error_code, created_at
FROM badge_calculation_logs
ORDER BY created_at DESC
LIMIT 50;
GitHub Actions ล็อก build/deploy/verify ของ UAT แท็บ Actions ของรีโป
อย่าค้นล็อกด้วย LINE user ID ดิบในช่องทางที่ไม่เข้ารหัส เทียบกับ hash จาก LOG_HASH_SECRET (หรือ session secret ถ้าไม่ตั้งตัวแรก) ตาม hashLineUuid

Monitoring

  • แพลตฟอร์ม: Health check path ที่คู่มือ UAT แนะนำคือ /api/health บน App Service
  • Always On ตามแผน Azure (ถ้ารองรับ)
  • ไม่มีเมตริกธุรกิจ (จำนวนเหรียญ, อัตรา error Sony) ในแอป
  • ไม่มี alert rule ในรีโป — ตั้งที่ Azure/องค์กรถ้าต้องการ

Support Flow

  1. ผู้ใช้: แถบล่าง FAQ → https://www.sony.co.th/microsite/digital-badge/ หรือลงทะเบียนสินค้าตาม NEXT_PUBLIC_ACCOUNT_URL
  2. ถ้าเหรียญไม่ตรง: อ่าน support_message บนหน้า (debug/ลูกค้าตามที่ UI แสดง) ไม่เปิด ?debug=1 ให้ผู้ใช้บน production (APP_ENV=production ปิดอยู่แล้ว)
  3. ฝ่ายปฏิบัติการ: ตรวจ health → Log stream → ตาราง badge_calculation_logs (เฉพาะเส้น customer-products) → โหมด Sony mock/live โดยไม่พิมพ์คีย์ในแชท
  4. เซสชัน: คุกกี้ sony_line_session อายุ 1 ชั่วโมง ให้เปิด Mini App ใน LINE ใหม่ถ้าหมดอายุ
  5. ถ้ายืนยันว่ากฎผิด: อย่าแก้แถวบนฐานลวก ๆ — แก้ seed, bump badge_rules_version, สำรอง, แล้ว seed ตาม runbook
  6. ถ้ายืนยันว่าแอปพังหลัง deploy: rollback ตาม Deployment Guide ไม่ใช้ db:reset
