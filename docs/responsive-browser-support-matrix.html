เป้าหมายการรองรับ (Support target)

  • หลัก: เปิด Mini App ในแอป LINE บนสมาร์ตโฟน (liff.isInClient() === true) มี ID token
  • รอง: หน้า OG /{locale}/share/... ให้ Facebook crawler และเบราว์เซอร์ทั่วไปอ่านเมตา
  • พัฒนา: Chrome/Safari บนเดสก์ท็อปเมื่อ APP_ENV=local + mock ไม่ต้องมี LIFF
โค้ดสร้างเซสชันจะ throw หากไม่ได้เปิดใน LINE client เบราว์เซอร์ภายนอก (Chrome/Safari นอกแอป LINE) จึงไม่ใช่ช่องทางผู้ใช้แคมเปญ แม้ LINE จะเริ่มเปิด Mini App นอกแอปได้ในบางภูมิภาค

Responsive (เลย์เอาต์ในแอป)

  • Viewport: width=device-width, initialScale=1, viewportFit=cover
  • ความสูงหน้า: min-height: 100dvh กันแถบที่อยู่ของ iOS
  • ระยะล่าง: env(safe-area-inset-bottom) บน My Badges, Products, Missions, รายละเอียด, loading
  • หน้าบ้าน/แคตตาล็อกสินค้า: กริด 3 คอลัมน์ (repeat(3, minmax(0, 1fr))) ไม่มี breakpoint แยกแท็บเล็ต
  • @media (max-width: 680px) ใช้กับหน้าวินิจฉัย BadgeClient ใน globals.css เป็นหลัก ไม่ได้ปรับกริด My Badges
ความกว้างจอที่ออกแบบไว้
ช่วงความกว้าง ระดับ หมายเหตุ
ประมาณ 360–430 px (โทรศัพท์แนวตั้ง) เป้าหมาย กริด 3 คอลัมน์การ์ดเหรียญ, แถบล่าง 3 ปุ่ม
แท็บเล็ต / แนวนอนกว้าง ไม่ได้ปรับเลย์เอาต์แยก เนื้อหายืดเต็มความกว้าง คอลัมน์การ์ดยังเป็น 3
เดสก์ท็อปกว้าง ใช้พัฒนา/mock ไม่ใช่ช่องทาง LIFF ของผู้ใช้

อุปกรณ์และระบบปฏิบัติการ

LINE กำหนดว่า LIFF ในแอปใช้ WKWebView (iOS) และ Android WebView เวอร์ชันต่ำสุดตามสเปกระบบที่แอป LINE รองรับในขณะนั้น แนะนำให้ใช้ OS และ LINE รุ่นล่าสุด

แพลตฟอร์ม สถานะแอปนี้ หมายเหตุ
iPhone + iOS (ล่าสุดที่ LINE รองรับ) รองรับ (เป้าหมาย) safe-area, 100dvh, แชร์ใช้ Web Share ก่อนเพราะลิงก์ Facebook บน iOS มักพังเมื่อมีแอป Facebook
Android phone (ล่าสุดที่ LINE รองรับ) รองรับ (เป้าหมาย) WebView ของระบบ; ลิงก์ภายนอกผ่าน liff.openWindow
iPad / Android tablet ไม่ได้ทดสอบเป็นเป้าหมาย ถ้า LINE บนเครื่องเปิด Mini App ได้ เลย์เอาต์ยังเป็นมือถือ 3 คอลัมน์
LINE PC / macOS / Chrome OS นอกขอบเขตผู้ใช้ เซสชันต้องการ in-client ของแอปมือถือ

เวอร์ชัน LINE และ LIFF

รายการ ค่าที่ใช้ ความหมายต่อแอปนี้
LIFF SDK ใน npm @line/liff ^2.27.1 (ติดตั้ง 2.29.x) Mini App ของ LINE รับ SDK ตระกูล 2.1 ขึ้นไป แอปใช้ init, getIDToken, getProfile, isInClient, openWindow
LINE แอป (แนะนำจาก LINE) รุ่นล่าสุด ต้องมี ID token ใน in-client
LINE แอป (ต่ำสุดจาก LINE) ตามสเปกระบบของแอป LINE ไม่ได้ล็อกเลขรุ่นในรีโปนี้ ไม่มีเช็กเวอร์ชันในโค้ด ถ้ารุ่นเก่าไม่มี ID token ผู้ใช้เข้าบ้านไม่ได้
LINE 26.7+ / 15.12+ UI ของ LIFF chrome เมนูหัว LIFF ของแพลตฟอร์ม ไม่เกี่ยวกับเลย์เอาต์เหรียญในหน้าเรา
OpenChat LINE ไม่รับรอง LIFF อย่างเป็นทางการ อย่าใช้เป็นช่องทางแคมเปญ
สเปกอย่างเป็นทางการ: LIFF overview — Recommended operating environment และ LINE MINI App specifications

Browser matrix

เบราว์เซอร์ บทบาท สถานะ
LIFF browser (WKWebView) ผู้ใช้ iOS ใน LINE รองรับ — ช่องทางหลัก
LIFF browser (Android WebView) ผู้ใช้ Android ใน LINE รองรับ — ช่องทางหลัก
Safari / Chrome / Edge / Firefox นอก LINE เปิด URL Mini App โดยตรง ไม่รองรับโฟลว์เหรียญ (ไม่มี in-client / ID token)
Facebook crawler / เบราว์เซอร์ทั่วไป หน้า /share/product|mission อ่าน OG ได้ ไม่ต้อง LIFF
Chrome หรือ Safari เดสก์ท็อป local mock พัฒนาเท่านั้น
Internet Explorer / เบราว์เซอร์รุ่นก่อน Chromium เก่ามาก — ไม่รองรับ (Next.js 14 / React 18)

โปรเจกต์ไม่มี browserslist ของตัวเอง ตามค่าเริ่มต้นของ Next.js 14

ฟีเจอร์ที่ขึ้นกับเบราว์เซอร์

ฟีเจอร์ ต้องการ พฤติกรรมสำรอง
สร้างเซสชัน LIFF in-client + ID token ข้อความเข้าถึงไม่ได้ / ไม่ตั้งคุกกี้
ลิงก์ Sony ภายนอก liff.openWindow window.open หรือเปลี่ยนหน้า
แชร์เหรียญ navigator.share ถ้ามี Facebook sharer ผ่าน LIFF แล้วจึง window.open
sessionStorage LINE uuid storage ของ WebView ถ้าถูกบล็อก ต้องพึ่งโปรไฟล์ LIFF ในรอบนั้น
คุกกี้เซสชัน HttpOnly SameSite=Lax บน HTTPS ของโฮสต์แอป หน้า my-* ยังส่ง lineuuid ใน query ได้อยู่

แนะนำชุดทดสอบ UAT อย่างน้อย: iPhone รุ่นปัจจุบันใน LINE ล่าสุด, Android รุ่นปัจจุบันใน LINE ล่าสุด, ทั้งแนวตั้ง และหนึ่งเคสแชร์เหรียญบน iOS ที่มีแอป Facebook ติดตั้ง
