Access Control Matrix

Role, สิทธิ์เข้าถึงข้อมูล และสิทธิ์จัดการระบบของ Sony Badge Pilot ตามที่โค้ดและขั้นตอนปฏิบัติการรองรับจริง

Pilot นี้ไม่มี CMS, ไม่มีตาราง user/role และไม่มี RBAC ในแอป ตัวตนใน Mini App คือ LINE user ID การเปลี่ยนกฎเหรียญทำผ่าน seed/config ที่รีวิวแล้ว ไม่มีหน้าแอดมิน

บทบาท (Roles)

บทบาทในแอป vs บทบาทปฏิบัติการ
Role ชนิด วิธีพิสูจน์ตัวตน หมายเหตุ
LINE Customer ในแอป LIFF ID token → cookie และ/หรือ sessionStorage LINE user ID ดูเหรียญของตนเอง ไม่แก้กฎ
Public visitor / OG crawler ในแอป ไม่มี session หน้าแชร์, health, ชั้นเหรียญแบบล็อกเมื่อไม่มี lineuuid
Local developer ในแอป (เฉพาะ APP_ENV=local) ข้าม LIFF ได้เมื่อ mock; /api/mock-session ใช้ไม่ได้บน staging/production
Omelet engineer ปฏิบัติการ Git repository access แก้ seed/โค้ด ส่ง PR ไม่มี UI แอดมิน
UAT deployer ปฏิบัติการ GitHub environment uat + publish profile deploy แอป ไม่รัน migrate ใน workflow
Database operator ปฏิบัติการ โฮสต์ที่เข้า Azure MySQL ได้ + DATABASE_URL migrate / seed / verify ด้วยมือ
Sony infra owner ปฏิบัติการ Azure App Service / APIM / MySQL ที่ Sony ถือสิทธิ์ เครือข่าย, TLS, subscription key, IP allowlist

สิ่งที่แอปบังคับเอง (Enforced in code)

จุดตรวจสิทธิ์
พื้นผิว ใครเข้าได้ กลไก
POST /api/line-session ไคลเอนต์ที่มี LINE ID token ใช้ได้ verify กับ LINE; ไม่มีรายการ role
GET /entry request ที่ Origin/Referer อยู่ใน allowlist และมี cookie evaluateRedirectGuard + resolveAuthorizedLineUuid
GET /api/customer-products มี cookie session; query lineuuid resolveAuthorizedLineUuid
GET /api/my-* มี lineuuid ใน query หรือได้ชั้นแบบล็อก ไม่ตรวจ cookie — ช่องว่างของโมเดลสิทธิ์
GET /share/... ทุกคน อ่านเฉพาะ metadata ของกฎ
GET /api/mock-session local + mock เท่านั้น อื่น ๆ ได้ 404
Debug JSON / trace ไม่ใช่ production isDebugModeEnabled คืน false เมื่อ APP_ENV=production
ไม่มี role admin ในฐานข้อมูล การจัดการกฎ = สิทธิ์ Git + สิทธิ์เข้า MySQL ลูกค้าไม่มีสิทธิ์ W/D ต่อข้อมูลกฎหรือข้อมูลคนอื่นผ่าน UI
