Eligible Product — สินค้าที่ร่วมรายการ

Eligible Product คือรุ่น Sony ที่เงื่อนไขเหรียญยอมรับ ระบบเทียบกับสินค้าที่ลูกค้าลงทะเบียนจาก warranty API โดยใช้ SKU ที่ normalize แล้ว

Field ที่ประกอบ Eligible Product
Field ชนิด ค่าที่อนุญาต / ตัวอย่าง ความหมาย
sony_skus JSON array ของ string ["SEL2870GM", "SEL50150GM"] รายการรุ่นที่ร่วมรายการในเงื่อนไขนี้ ไม่มีตาราง SKU แยก
match_type VARCHAR(40) any, all, min_count วิธีนับสินค้าใน list นี้
required_count (condition) INT, default 1, ต้อง ≥ 0 1, 3, 4 จำนวนที่ต้องมีใน list นี้ ถ้า match_type = 'all' ระบบใช้ความยาวของ sony_skus แทน
condition_label VARCHAR(255) Own one 16-35 GM family model ป้ายให้อ่านใน SQL / debug ไม่ได้ใช้คำนวณ
product_model_code VARCHAR(120), nullable SEL100M28GM รหัสรุ่นหลักของเหรียญผลิตภัณฑ์ ใช้แสดงผล ไม่แทนที่ sony_skus

วิธีนับในหนึ่งเงื่อนไข (Match type)

match_type ความหมายธุรกิจ ตัวอย่าง seed
any มีสินค้าใดสินค้าหนึ่งใน list ตาม required_count (มักเป็น 1) The Magnifier: macro รุ่นใดก็ได้ 1 ชิ้น
all ต้องมีครบทุก SKU ใน list F2 Master: ต้องมีทั้ง SEL2870GM และ SEL50150GM
min_count ต้องมีอย่างน้อย N รุ่นที่ไม่ซ้ำจาก list All Rounder: 3 จาก 4 รุ่น; Portrait Master Gold: สะสมถึง 4 รุ่น
นับรุ่นไม่ซ้ำ (unique SKU) สินค้าที่ match SKU เดียวกันนับได้ครั้งเดียวต่อเงื่อนไข ลงทะเบียนซีเรียลซ้ำของรุ่นเดียวกันจึงไม่เพิ่ม matched count
เทียบ SKU แบบ suffix-aware ระบบ uppercase + trim แล้วยอมรับส่วนท้ายแคตตาล็อก เช่น /QSYX แต่ SEL70200GM จะไม่ match SEL70200G
หลายเงื่อนไขในกฎเดียว แต่ละ condition มี Eligible Product ของตัวเอง matched count ของกฎคือผลรวมที่ cap ตาม required ของแต่ละ condition เช่น Trinity Master = หนึ่งรุ่นจากสามตระกูล GM
SKU เดียวกันไปอยู่ในหลายเหรียญได้ เช่นเลนส์ G Master อาจนับทั้งเหรียญผลิตภัณฑ์และ quest

Threshold — เกณฑ์ปลดล็อก

Threshold คือระดับที่เหรียญจะเปลี่ยนจากยังไม่ปลดล็อกเป็นปลดล็อก เมื่อ matched count ของทั้งกฎ ถึง required_count ของระดับนั้น

Field ของ Threshold
Field ชนิด ค่าที่อนุญาต / ตัวอย่าง ความหมาย
level VARCHAR(80), unique ต่อกฎ achievement, bronze, silver, gold รหัสระดับ คงที่สำหรับ UI / ลิงก์รายละเอียด
display_name VARCHAR(255) Portrait Master Gold ชื่อที่แสดงเมื่ออยู่ที่ระดับนี้
required_count (threshold) INT, ต้อง ≥ 0 เหรียญผลิตภัณฑ์ = 1; Portrait Master = 2 / 3 / 4 matched count ขั้นต่ำเพื่อปลดล็อกระดับนี้
achieved_image_url TEXT, nullable /quest-badge/portrait-gold.png รูปสีเมื่อปลดล็อกแล้ว
locked_image_url TEXT, nullable null ใน seed ปัจจุบัน รูปตอนยังไม่ปลดล็อก ถ้าว่างระบบใช้รูป achieved แล้วลดความสว่าง
share_image_url TEXT, nullable มักซ้ำกับ achieved รูปแชร์ / OG
sort_order INT 1001, 1002, 1003 ลำดับแสดง ถ้า required_count เท่ากัน ระบบเรียงด้วยค่านี้
Required Count มีสองชั้น: ของ condition จำกัดว่าเงื่อนไขหนึ่งข้อให้นับได้เท่าไร ของ threshold ตัดสินว่าระดับไหนปลดล็อก ตัวอย่าง The Visionary: condition min_count 4 จากรายการ telephoto แล้ว threshold bronze=2, silver=3, gold=4
เหรียญผลิตภัณฑ์ Threshold เดียว level = achievement, required_count = 1 มี Eligible Product รุ่นเดียว
เหรียญ quest แบบ achievement Threshold เดียวเช่นกัน แต่ required_count อาจเป็น 2 หรือ 3 เช่น Trinity Master ต้องครบ 3 ตระกูล

Tier — ระดับเหรียญ

Tier คือกฎที่มีหลาย Threshold จาก Eligible Product ชุดเดียวกัน ลูกค้าสะสมรุ่นไม่ซ้ำแล้วขยับจาก Bronze → Silver → Gold

Field ที่ทำให้กฎเป็น Tier
Field ค่า ความหมาย
badge_rules.rule_type tier หรือ achievement tier = มีหลายระดับที่มองเห็น achievement = ปลดล็อกก้อนเดียว
badge_rules.badge_type product หรือ quest ชนิดบนชั้นเหรียญ ไม่ได้บอกว่ามีกี่ระดับ seed ปัจจุบันใช้ tier กับ quest เท่านั้น
จำนวนแถว threshold มากกว่า 1 สำหรับ quest แบบสะสม แต่ละแถวคือหนึ่ง tier พร้อมรูปและ required count ของตัวเอง
ตัวอย่าง tier จาก seed ปัจจุบัน
Badge Bronze Silver Gold
Portrait Master 2 รุ่น 3 รุ่น 4 รุ่น
Wide Architect 3 รุ่น 4 รุ่น 5 รุ่น
The Visionary 2 รุ่น 3 รุ่น 4 รุ่น
Engine เรียง threshold ตาม required_count แล้วเลือกอันสูงสุดที่ matched count ถึง ยังไม่ถึงระดับแรกเลยจะยังเป็น locked ที่ threshold ถัดไป

Status — สถานะ

ในพจนานุกรมกฎ Status คือการเปิด/ปิดกฎทั้งก้อน ไม่ใช่สถานะเหรียญของลูกค้าคนหนึ่ง

Status ระดับ configuration
Field ชนิด ค่า ผลต่อระบบ
badge_rules.is_active BOOLEAN, default TRUE true / false false = กฎไม่เข้าการคำนวณและไม่โชว์บนชั้นเหรียญ ควรปิดกฎที่เคยแสดงแล้ว แทนการลบแถว
badge_display_groups.is_active BOOLEAN, default TRUE true / false ควบคุมกลุ่มแสดงผล ไม่ได้ปิดกฎลูกโดยอัตโนมัติผ่าน FK
Status ระดับ runtime (คำนวณ ไม่ persist ในตารางกฎ)
ค่า ความหมาย เงื่อนไขโดยย่อ
earned ปลดล็อกแล้ว (achieved) matched count ≥ threshold อย่างน้อยหนึ่งระดับ
locked เริ่มสะสมแล้วแต่ยังไม่ถึงเกณฑ์ matched count > 0 แต่ยังไม่ถึง threshold ใด
no-badge ยังไม่มีสินค้าที่ร่วมรายการ matched count = 0
กฎที่ is_active = false จะไม่ถูกคำนวณเลย จึงไม่มี earned/locked ปิดกฎไม่ลบประวัติสินค้าที่ Sony API เพราะ ownership ไม่อยู่ในฐานข้อมูลนี้

Effective Date — วันที่มีผล

ระบบแยกวันที่เป็นสองหน้าต่าง เพราะ “เหรียญโชว์บนชั้นเมื่อไร” กับ “สินค้านับเมื่อไร” ไม่ใช่เรื่องเดียวกัน

หน้าต่างแสดงผล (Display window)
Field ชนิด เทียบกับ ความหมาย
active_from DATE, nullable วันปัจจุบันของเซิร์ฟเวอร์ (now) ก่อนวันนี้กฎยังไม่โชว์ / ไม่คำนวณ
active_to DATE, nullable วันปัจจุบันของเซิร์ฟเวอร์ หลังวันนี้เหรียญหายจากชั้น ปล่อยว่างถ้าต้องการโชว์ต่อหลังแคมเปญ
หน้าต่างลงทะเบียน (Earning / registration window)
Field ชนิด เทียบกับ ความหมาย
registration_start DATE, nullable Sony product registeredAt สินค้าที่ลงก่อนวันนี้ไม่นับเป็น Eligible Product ของกฎนี้
registration_end DATE, nullable Sony product registeredAt สินค้าที่ลงหลังวันนี้ไม่นับ ถ้าลงในหน้าต่างแล้วยังโชว์เหรียญที่ได้ภายหลังได้
ค่า null = ไม่จำกัด Seed ปัจจุบันใส่ null ทั้งสี่คอลัมน์ สินค้าที่ลงทะเบียนแล้วจึงนับได้ทุกวัน และเหรียญโชว์ตลอดที่กฎยัง active
ขอบเขตวันที่รวมวันปลาย ระบบเทียบแบบวันที่ (UTC midnight ของค่าที่เก็บ) สินค้าที่ลงในวัน registration_end ยังนับ
ตัวอย่างแคมเปญระยะสั้น: ตั้ง registration_start/end ตามช่วงลงทะเบียน และปล่อย active_to เป็น null เพื่อให้ผู้ที่ได้เหรียญแล้วยังเห็นบนชั้น ใส่ active_to เมื่อต้องการให้เหรียญหายจากชั้นหลังจบแคมเปญ

ลำดับที่ระบบใช้ field เหล่านี้

  1. Status — ถ้า is_active เป็น false จบที่กฎนี้
  2. Effective Date (แสดงผล) — ถ้าวันนี้ไม่อยู่ในช่วง active_from / active_to จบที่กฎนี้
  3. Eligible Product — คัดสินค้าที่ SKU ตรง list และอยู่ในหน้าต่างลงทะเบียน นับรุ่นไม่ซ้ำตาม match_type
  4. Threshold / Tier — เทียบ matched count กับ required_count ของแต่ละระดับ แล้วเลือกสูงสุดที่ถึง
หลังแก้ field เหล่านี้ในฐานข้อมูล ต้อง bump app_config.badge_rules_version เพื่อไม่ให้ cache ใช้กฎเก่า
