Screen Flow / User Flow

เส้นทางตั้งแต่เข้าใช้งาน เชื่อมสมาชิก ดูเหรียญ ดู Tier และแชร์เหรียญ ใน LINE Mini App

บ้านของแคมเปญคือ /{locale}/my-badges สมาชิกในแอปคือ LINE user ที่ผูกกับสินค้าผ่าน Sony warranty API ไม่มีหน้าสมัครสมาชิกใน Mini App

เส้นทางหลัก (Happy path)

เปิด Mini App ใน LINE
  → LIFF init + ID token
  → POST /api/line-session  (คุกกี้เซสชัน 1 ชม.)
  → เก็บ LINE user id ฝั่งไคลเอนต์
  → /{locale}/my-badges
  → GET /api/my-badges?lineuuid=
       ├─ LINE verify แล้ว (ครั้งเข้า)
       └─ Sony QueryWarrantyMySonyByLine + กฎ MySQL
  → เห็นโปรไฟล์ + นับเหรียญ + พรีวิว

แตกได้สี่ทางจากบ้าน:
  A. ดูเหรียญสินค้าทั้งหมด / รายละเอียด / แชร์
  B. ดูภารกิจ + ชั้น (Tier) / รายละเอียดชั้น / แชร์เมื่อครบ
  C. แถบ Register → เว็บลงทะเบียนสินค้า Sony (ออกจาก Mini App)
  D. แถบ FAQ → microsite

เข้าใช้งาน (Entry)

  1. ผู้ใช้เปิดจาก LINE (LIFF ID) middleware ดึง / และ /badge ไป /th/my-badges
  2. Production ที่เข้า /{locale}/badges จะเห็นหน้าโหลด BadgeSessionBootstrap จนกว่า verify ID token สำเร็จ แล้ว router.replace ไป My Badges
  3. ทุกหน้าภายใต้ /{locale} มี LineSessionProvider ทำ LIFF อีกครั้งถ้ายังไม่มีเซสชันในหน่วยความจำ
  4. My Badges แสดง skeleton จนกว่า status ไม่ใช่ idle/loading และมี lineUuid แล้วจึงยิง API
จุดเข้าที่เป็นไปได้
จุดเข้า จอถัดไป
ไอคอน Mini App / deep link บ้าน My Badges (หลัง LIFF)
/{locale}/entry ถ้า origin/referrer ผ่านและมีคุกกี้ → badges แล้วต่อไปบ้าน ถ้าไม่ผ่าน → badges พร้อมข้อความเข้าถึงไม่ได้
Deep link ชั้นภารกิจ /{locale}/my-missions/{tierId} ยังต้องมี LINE id เพื่อคำนวณความคืบหน้า

เชื่อมสมาชิก (Membership)

ระบบไม่เก็บบัญชีลูกค้าเอง “สมาชิก” คือ LINE ID ที่ Sony ใช้ค้น warranty 

เชื่อม LINE (ในแอป)
  LIFF getIDToken → LINE Login verify → คุกกี้ sony_line_session
  + โปรไฟล์ displayName / pictureUrl บนการ์ดบ้าน

ผูกสินค้า (นอกแอป)
  ลูกค้าต้องลงทะเบียนสินค้าบนระบบ Sony อยู่แล้ว
  แอปเรียก APIM ด้วย { countryCode, lineId } ทุกครั้งที่โหลด my-*
  ไม่มีหน้า “เชื่อมบัญชี Sony” ใน Mini App

เพิ่มสินค้าใหม่
  แถบล่าง Register → NEXT_PUBLIC_ACCOUNT_URL
  หรือปุ่มลงทะเบียนบนหน้ารายละเอียดภารกิจที่ยังไม่ครบ
    → NEXT_PUBLIC_REGISTER_PRODUCT_URL
  เมื่อกลับมา Mini App โหลดหน้าใหม่จึงดึง warranty รอบใหม่
ไม่มี login ด้วยอีเมล/รหัสผ่านในแอป ถ้า LINE ยังไม่ผูกกับรายการ warranty Sony จะเห็นแคตตาล็อกล็อกหรือวิวว่าง ไม่มีหน้า wizard เชื่อมสมาชิกแยก

ดูเหรียญ (View badges)

My Badges
  ├─ สถิติ Product ได้/ทั้งหมด, Quest ชั้นที่ achieved/ทั้งหมด
  ├─ พรีวิวสินค้าล่าสุดสูงสุด 3 (เรียงวันใหม่ก่อน, วันเดียวกันเรียงชื่อ)
  │     ดูทั้งหมด → My Products (กรองกลุ่ม)
  │     การ์ด → Product detail (เฉพาะที่ปลดล็อกในพรีวิว)
  └─ พรีวิวภารกิจล่าสุดสูงสุด 3 (ชั้นสูงสุดที่ได้แล้ว)
        ดูทั้งหมด → My Missions

แคตตาล็อกสินค้า: เหรียญล็อกกดไม่ได้ เหรียญปลดล็อกเข้าหน้ารายละเอียด เห็นวันปลดล็อกและจำนวน serial

ดู Tier

My Missions
  แต่ละ Quest เป็นแถวชั้น
    Portrait / Wide / Visionary → Bronze, Silver, Gold
    Quest ชุด → ชั้นเดียว (achievement)
  ตัวเลข progress/target บนแต่ละโหนด
  กดชั้นใดก็ได้ (รวมที่ยังไม่ครบ)

รายละเอียดชั้น  /my-missions/{quest}-{level}
  ยังไม่ครบ → การ์ดสรุป + รายการรุ่น (ตั๋ว) + ลงทะเบียนสินค้า + กลับรายการภารกิจ
  ครบแล้ว   → เลย์เอาต์ได้รับเหรียญ + แชร์ + กลับบ้าน

จากบ้าน: การ์ดภารกิจพรีวิวไปชั้นสูงสุดที่ได้ ไม่ได้ไปหน้าแทร็กทั้งหมด

สถานะภาพโหนด: ครบเกณฑ์ชั้นนั้นเป็นสีเต็ม (unlocked) ยังไม่ครบเป็น partial การคำนวณชั้นเป็น unique รุ่นตามกฎ Quest ไม่ใช่จำนวน serial

แชร์เหรียญ (Share)

ได้เหรียญสินค้า  → Product detail → ปุ่มแชร์ Facebook
ได้ชั้นภารกิจ    → Mission detail (โหมดครบ) → ปุ่มแชร์ Facebook

ลำดับในปุ่ม:
  1. ระบบ share sheet ของเครื่อง (navigator.share) ถ้ามี — ผู้ใช้เลือก Facebook เอง
  2. ไม่ได้ → LIFF openWindow ไป Facebook sharer
  3. ไม่ได้ → window.open / เปลี่ยนหน้า

สิ่งที่แชร์: URL รูปเหรียญแบบ absolute (shareImageUrl)
ไม่ใช่ลิงก์ Mini App และไม่บังคับเปิดหน้า /share/...

หน้า /{locale}/share/product/{id} และ /{locale}/share/mission/{id} เป็นหน้า OG สำหรับ crawler ถ้ามีการแชร์ URL นั้น ไม่ได้อยู่ในปุ่มแชร์ของโฟลว์หลัก

ปุ่มแชร์ disabled เมื่อสร้าง URL รูปไม่ได้ ภารกิจที่ยังไม่ครบไม่มีปุ่มแชร์ สินค้าที่ล็อกในแคตตาล็อกเข้าหน้าแชร์ไม่ได้

เส้นทางแยก (Exceptions)

เหตุ เส้นทางที่ผู้ใช้เจอ
เปิดนอก LINE / ไม่มี ID token หน้า badges ค้างข้อความเข้าถึงไม่ได้ หรือ My Badges โหลดแล้ววิวว่าง
Sony ไม่พบลูกค้า / API ล้ม บน my-products, my-missions แคตตาล็อกล็อกทั้งชุด (ดูเหมือนยังไม่ได้เหรียญ)
Sony ล้ม บน my-badges HTTP error → วิวว่าง ไม่มีปุ่มลองใหม่
เปิดรายละเอียดสินค้าที่ยังไม่ปลดล็อก API 404 → PageError
ไม่มี URL ลงทะเบียนใน env ไม่แสดงปุ่มลงทะเบียนบนภารกิจ; แถบล่าง Register อาจไม่มี href

Frontend Functional Specification

รายการหน้าจอ ฟังก์ชัน ปุ่ม เงื่อนไขการแสดงผล และ Navigation ของ LINE Mini App

หน้าหลักของผู้ใช้คือ /{locale}/my-badges ไม่ใช่เส้นทางเก่า /badge

  • แผนนำทาง (Navigation)
  • พฤติกรรมร่วม
  • รายการหน้าจอ
  • เงื่อนไขแสดงผล
  • ปุ่มและการกระทำ

แผนนำทาง (Navigation map)

 /  และ /badge  →  /th/my-badges   (middleware)
 /{locale}/badges
    ├─ local + mock     → /{locale}/my-badges
    ├─ production LIFF  → bootstrap เซสชัน แล้ว replace my-badges
    └─ ?debug=1         → BadgeClient (วินิจฉัย)
 /{locale}/entry        → ตรวจ referrer/เซสชัน แล้วไป badges หรือ badges?entryError=
 /{locale}/my-badges    ← บ้าน (Home)
    ├─ ดูทั้งหมดสินค้า  → /{locale}/my-products
    ├─ การ์ดสินค้าล่าสุด → /{locale}/my-product/{productId}
    ├─ ดูทั้งหมดภารกิจ  → /{locale}/my-missions
    └─ การ์ดภารกิจล่าสุด → /{locale}/my-missions/{tierId}
 /{locale}/my-products  → กรองกลุ่ม → เฉพาะ unlocked ไปรายละเอียดสินค้า
 /{locale}/my-missions  → ทุกชั้น (bronze/silver/gold/achievement) ไปรายละเอียดภารกิจ
 /{locale}/share/...    → หน้า OG สำหรับ Facebook (ไม่ใช่โฟลว์ใน LIFF หลัก)
Redirect ที่ระบบทำให้อัตโนมัติ
จาก ไป เมื่อ
/, /badge, /my-badges /th/my-badges middleware (locale เริ่มต้น th)
/entry /th/entry middleware
/{locale}/badges?mock=1 /api/mock-session เฉพาะ local + Sony mock

พฤติกรรมร่วม (Cross-cutting)

  • LineSessionProvider ครอบทุกหน้าใน /{locale}/* — init LIFF, ตั้งคุกกี้ผ่าน POST /api/line-session, เก็บ LINE user id ใน sessionStorage
  • หน้า my-* ดึงข้อมูลด้วย lineuuid ใน query (ไม่ผูกคุกกี้ที่ route) ระหว่าง idle/loading แสดง PageLoading
  • ลิงก์ภายนอกใน LIFF ใช้ liff.openWindow({ external: true }) ผ่าน ExternalLink

รายการหน้าจอ (Screens)

SC-01 · My Badges — /{locale}/my-badges

หน้าที่บ้านของแคมเปญ ฟังก์ชัน: แสดงโปรไฟล์ LINE, นับเหรียญที่ได้/ทั้งหมด, พรีวิวสินค้าและภารกิจอย่างละไม่เกิน 3 รายการล่าสุด, แถบนำทางล่าง

  • การ์ดโปรไฟล์: รูปจาก LIFF ถ้ามี ไม่เช่นนั้นตัวอักษรแรกของชื่อ
  • สถิติ: Product ได้/ทั้งหมด และ Mission (นับชั้นที่ achieved)
  • ดูทั้งหมด → รายการเต็มสินค้า / ภารกิจ
  • แถบล่าง Home (หน้านี้) / Register / Inquiry

SC-02 · My Products — /{locale}/my-products

แคตตาล็อก Product Badge ทั้งกลุ่ม มีตัวกรอง all, full-frame-camera, prime-lens, wide-normal-zoom-lens, telephoto-super-telephoto-lens, macro-lens

การ์ดที่ unlocked และมีรูปกดได้ การ์ดล็อกแสดงโดยไม่มีรูปและกดไม่ได้

SC-03 · Product detail — /{locale}/my-product/{productId}

แสดงเมื่อ API คืนข้อมูลสินค้าที่ปลดล็อกแล้ว ชื่อเหรียญ, วันปลดล็อก, จำนวน serial, ปุ่มแชร์ Facebook, กลับบ้าน

SC-04 · My Missions — /{locale}/my-missions

แปดส่วนตาม Quest (Portrait, Wide, Visionary, Trinity Master/Junior, All Rounder, F2, Magnifier) แต่ละส่วนมีแทร็กชั้น กดชั้นใดก็ได้รวมที่ยังไม่ครบ เพื่อเข้าหน้ารายละเอียดชั้นนั้น

SC-05 · Mission detail — /{locale}/my-missions/{missionId}

สองเลย์เอาต์ตามความคืบหน้าของชั้นนั้น:

  • ยังไม่ครบ (progress < target): การ์ดสรุป, ปุ่มลงทะเบียนสินค้า (ถ้ามี URL), รายการตั๋วรุ่น, ปุ่มกลับไป My Missions
  • ครบแล้ว: เลย์เอาต์คล้ายรายละเอียดสินค้า — แชร์ Facebook, กลับบ้าน (My Badges)

SC-06 · LIFF bootstrap — /{locale}/badges

Production: หน้าโหลด/บล็อกระหว่างสร้างเซสชัน แล้วไป My Badges Local mock: redirect ตรงไป My Badges ?debug=1: UI วินิจฉัย BadgeClient

SC-07 · Entry guard — /{locale}/entry

ไม่มี UI คงที่ ตรวจ referrer/origin แล้ว redirect ถ้าไม่ผ่านไป badges?entryError=

SC-08 · Share OG — /{locale}/share/product|mission/{id}

หน้าสาธารณะสำหรับ crawler Facebook แสดงชื่อ/คำอธิบายแคมเปญและรูปเหรียญ ถ้าไม่มี meta → notFound

SC-09 · Loading / Error

PageLoading ตาม variant ของหน้า รายละเอียดสินค้าที่ API ไม่สำเร็จใช้ PageError My Badges เมื่อโหลดไม่สำเร็จยังเรนเดอร์วิวว่าง (interactive) ไม่ใช้ PageError My Products / My Missions เมื่อ isLoading หรือยังไม่มี data วนที่ loading (รวมกรณี error ของ hook ที่ไม่มี data)

เงื่อนไขการแสดงผล (Display rules)

พื้นที่ เงื่อนไข สิ่งที่ผู้ใช้เห็น
My Badges พรีวิว ไม่มีเหรียญล่าสุด ข้อความว่างของหมวด
My Badges การ์ด มีรายการ และ interactive ลิงก์ไปรายละเอียด (สินค้าใช้รหัสกฎ, ภารกิจใช้รหัสชั้น)
Product catalog status unlocked + มี imageUrl รูปสี + ลิงก์รายละเอียด
Product catalog locked หรือไม่มีรูป การ์ดไม่มีรูป, aria-disabled, ไม่มีลิงก์
ตัวกรองสินค้า เลือกกลุ่มหนึ่ง เหลือหมวดนั้นหมวดเดียว
Mission node progress ≥ target และ target > 0 คลาส visual unlocked
Mission node ยังไม่ครบ คลาส partial (โค้ดไม่ใช้สถานะ empty)
ตั๋วภารกิจ status completed ป้าย completed ไม่มีลิงก์รายละเอียด
ตั๋วภารกิจ pending + มี productUrl ลิงก์ Details ออกเว็บ Sony
ตั๋วภารกิจ pending ไม่มี productUrl ข้อความ Details แบบ disabled
ปุ่มลงทะเบียนบนภารกิจ ไม่มี LIFF ID หรือไม่มี REGISTER URL ไม่เรนเดอร์ปุ่ม
วันปลดล็อกภารกิจที่ครบ ไม่มี unlockedAt ไม่แสดงบรรทัดวันที่
แชร์ Facebook สร้าง URL รูปไม่ได้ ปุ่ม disabled
โปรไฟล์ มีรูป LINE avatar รูป
handle ว่างเสมอใน API ปัจจุบัน ไม่แสดงบรรทัด handle

ปุ่ม / ลิงก์ หน้า ปลายทาง
ดูทั้งหมด (สินค้า) My Badges /{locale}/my-products
ดูทั้งหมด (ภารกิจ) My Badges /{locale}/my-missions
Home แถบล่าง My Badges /{locale}/my-badges

Inquiry แถบล่าง https://www.sony.co.th/microsite/digital-badge/ (hardcode)

Frontend Configuration Guide

LIFF ID, Environment Variable และ Configuration ที่ต้องตั้งค่า ค่าในเอกสารนี้เป็นตัวแทน (placeholder) ไม่ใส่ secret จริง

ตัวแปรที่ขึ้นต้น NEXT_PUBLIC_* ถูกฝังตอน npm run build อย่าใส่คีย์ API, รหัสผ่านฐานข้อมูล หรือ session secret ในชื่อนี้

  • กฎปกปิด Secret
  • LIFF ID
  • ตัวแปรฝั่งเบราว์เซอร์
  • ตัวแปรเซิร์ฟเวอร์ที่หน้าบ้านพึ่งพา
  • ตั้งค่า LINE Developers
  • ตัวอย่างไฟล์ env

กฎปกปิด Secret

  • ไม่ commit .env, .env.production, .env.uat ใช้ GitHub environment secret UAT_ENV_FILE สำหรับ UAT
  • ไม่ใส่ SONY_PRODUCT_API_SUBSCRIPTION_KEY, DATABASE_URL, APP_SESSION_SECRET, LOG_HASH_SECRET, publish profile Azure ในเอกสารสาธารณะหรือ NEXT_PUBLIC_*
  • LIFF ID และ URL บัญชี Sony ปรากฏใน JavaScript ของเบราว์เซอร์ได้ตามออกแบบ แต่เอกสารนี้ใช้ placeholder ไม่คัดลอกค่าโปรดักชัน
  • Azure App Service ถ้ามี env จริง จะทับค่าในไฟล์ แต่ NEXT_PUBLIC_* ยังต้องมีตอน build

LIFF ID

ตัวแปร: NEXT_PUBLIC_LIFF_ID รูปแบบที่สคริปต์ deploy ตรวจ: ขึ้นต้นด้วย {LINE_CHANNEL_ID}- เช่น <channel-id>-<liff-suffix>

สภาพแวดล้อม ต้องมีหรือไม่ ผลถ้าไม่ตั้ง
local ไม่บังคับ LineSessionProvider เป็น unavailable หน้า badges โหมด local+mock ไป My Badges โดยไม่ผ่าน LIFF
staging / production บังคับ loadAppConfig throw NEXT_PUBLIC_LIFF_ID is required outside local mode.

โค้ดที่อ่านค่านี้ฝั่งไคลเอนต์:

  • liff.init({ liffId }) ใน src/lib/liff-session.ts
  • สร้างเซสชันและโปรไฟล์ใน LineSessionProvider
  • deep link กลับภารกิจ https://miniapp.line.me/{liffId}/th/my-missions/...
  • แชร์ Facebook ผ่าน liff.openWindow
Channel ID (LINE_CHANNEL_ID) ใช้ที่เซิร์ฟเวอร์ตอน verify ID token ไม่ใส่ NEXT_PUBLIC_ ต้องเป็นตัวเลข และต้องเป็นเจ้าของ LIFF เดียวกัน

ตัวแปรที่ฝังใน Frontend (NEXT_PUBLIC_*)

ค่าที่เบราว์เซอร์อ่านได้ — ไม่ใช่ secret
ตัวแปร ใช้ทำอะไร ตัวอย่างรูปแบบ (ไม่ใช่ค่าจริง)
NEXT_PUBLIC_LIFF_ID init LIFF, deep link Mini App <channel-id>-<liff-id>
NEXT_PUBLIC_APP_BASE_URL origin สำหรับ URL รูปแชร์ / OG next.config.mjs สำรองจาก APP_BASE_URL https://<public-host> ไม่มี path ท้าย
NEXT_PUBLIC_ACCOUNT_URL ลิงก์แถบล่าง Register (ลงทะเบียนสินค้า / บัญชี Sony) HTTPS เต็มของหน้าภายนอก
NEXT_PUBLIC_REGISTER_PRODUCT_URL ปุ่มลงทะเบียนบนหน้ารายละเอียดภารกิจที่ยังไม่ครบ HTTPS เต็ม; ถ้าว่างไม่แสดงปุ่ม
NEXT_PUBLIC_DEBUG_MOCK_JSON ธงดีบักฝั่งเซิร์ฟเวอร์ร่วมกับ query deploy ต้องเป็น false false บน UAT/production

ถ้า NEXT_PUBLIC_ACCOUNT_URL ว่าง แถบ Register ไม่มี href ที่ใช้ได้ ถ้า NEXT_PUBLIC_APP_BASE_URL ไม่ตรง APP_BASE_URL สคริปต์ verify-deploy-env.mjs จะไม่ผ่าน และ URL แชร์อาจผิดโฮสต์

ตัวแปรเซิร์ฟเวอร์ที่ Frontend พึ่งพา (ไม่ฝังใน JS)

หน้าบ้านเรียก API ของแอป ค่าเหล่านี้ต้องมีบนเซิร์ฟเวอร์/ตอน build ตามสภาพแวดล้อม ห้าม ใส่ใน NEXT_PUBLIC_*

ตัวแปร ชั้น ผลต่อหน้าจอ
APP_ENV ไม่ลับ (ค่า local/staging/production) local+mock ข้าม LIFF ไปพรีวิว ไม่รับค่า uat
APP_BASE_URL URL สาธารณะ ต้องตรงกับ origin ที่ LINE และ Facebook เรียกได้
ALLOWED_ORIGINS / ALLOWED_REFERRERS รายการ origin หน้า /entry บล็อกแหล่งที่ไม่ได้อนุญาต
LINE_CHANNEL_ID ไม่ใช่รหัสผ่าน แต่ไม่ควรโฆษณาในเอกสาร verify ID token ล้ม → ผู้ใช้เข้า Mini App ไม่ผ่าน
LINE_VERIFY_ID_TOKEN_URL ค่าเริ่มต้น LINE มาตรฐาน ค่าเริ่มต้นในโค้ด https://api.line.me/oauth2/v2.1/verify
APP_SESSION_SECRET Secret ≥ 32 ตัวอักษรตอน deploy เซ็นคุกกี้ sony_line_session
LOG_HASH_SECRET Secret ≥ 32 ตัวอักษรตอน deploy hash LINE ID ใน log ไม่เกี่ยวกับ UI โดยตรง
SONY_PRODUCT_API_* คีย์สมัครสมาชิก APIM เป็น secret โหมด live ล้ม → my-* อาจเป็นแคตตาล็อกล็อก / วิวว่าง
DATABASE_URL / DATABASE_SSL Secret + TLS ไม่มีกฎเหรียญ → หน้าแคตตาล็อกว่างหรือ error

Configuration บน LINE Developers (นอกไฟล์ env)

  • สร้าง LIFF / Mini App ภายใต้ Messaging API หรือ LINE Login channel เดียวกับ LINE_CHANNEL_ID
  • Endpoint / Mini App URL ชี้ origin เดียวกับ NEXT_PUBLIC_APP_BASE_URL เช่น https://<host>/th/my-badges
  • Scopes ที่แอปใช้จริง: ID token (openid) และโปรไฟล์สำหรับชื่อกับรูป
  • เปิดใช้งานใน LINE client เท่านั้น — โค้ดปฏิเสธเมื่อ liff.isInClient() เป็นเท็จ

เป้าหมายออกแบบคือโทรศัพท์ใน LIFF browser ของแอป LINE แพ็กเกจใช้ @line/liff ^2.27 (ล็อกใน lockfile เป็น 2.29.x) เอกสารนี้รวมข้อจำกัดในโค้ดกับสภาพแวดล้อมที่ LINE แนะนำ ไม่ใช่ผลแล็บอุปกรณ์ที่ลงนามในรอบนี้

เป้าหมายการรองรับ (Support target)

  • หลัก: เปิด Mini App ในแอป LINE บนสมาร์ตโฟน (liff.isInClient() === true) มี ID token
  • รอง: หน้า OG /{locale}/share/... ให้ Facebook crawler และเบราว์เซอร์ทั่วไปอ่านเมตา
  • พัฒนา: Chrome/Safari บนเดสก์ท็อปเมื่อ APP_ENV=local + mock ไม่ต้องมี LIFF
โค้ดสร้างเซสชันจะ throw หากไม่ได้เปิดใน LINE client เบราว์เซอร์ภายนอก (Chrome/Safari นอกแอป LINE) จึงไม่ใช่ช่องทางผู้ใช้แคมเปญ แม้ LINE จะเริ่มเปิด Mini App นอกแอปได้ในบางภูมิภาค

Responsive (เลย์เอาต์ในแอป)

  • Viewport: width=device-width, initialScale=1, viewportFit=cover
  • ความสูงหน้า: min-height: 100dvh กันแถบที่อยู่ของ iOS
  • ระยะล่าง: env(safe-area-inset-bottom) บน My Badges, Products, Missions, รายละเอียด, loading
  • หน้าบ้าน/แคตตาล็อกสินค้า: กริด 3 คอลัมน์ (repeat(3, minmax(0, 1fr))) ไม่มี breakpoint แยกแท็บเล็ต
  • @media (max-width: 680px) ใช้กับหน้าวินิจฉัย BadgeClient ใน globals.css เป็นหลัก ไม่ได้ปรับกริด My Badges
