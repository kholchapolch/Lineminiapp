Backup & Rollback Plan

วิธีสำรองและย้อนกลับข้อมูล หากพบปัญหา

Seed ทำงานในธุรกรรม: ถ้า script ล้มจะ rollback การเปลี่ยนแปลงรอบนั้น ถ้า commit แล้วแล้วพบว่ากฎผิด ต้องกู้จากสำเนาหรือ seed เวอร์ชันก่อนใน Git ไม่มี คำสั่ง rollback อัตโนมัติใน npm

สิ่งที่ seed ทำลายได้

  • แทนที่กลุ่มแสดงผลทั้งตาราง
  • ลบ thresholds/conditions ของกฎที่ถูก seed แล้วใส่ใหม่
  • ลบกฎที่ไม่อยู่ในไฟล์ seed (ลูกถูกลบด้วย ON DELETE CASCADE)
  • ไม่ลบ badge_calculation_logs
npm run db:reset DROP ตารางแอปทั้งหมดรวมปูมคำนวณ ห้ามใช้บน UAT/production

สำรองก่อนอัปเดต (Backup)

ใช้ mysqldump หรือเครื่องมือเทียบเท่าของ Azure ใส่โฮสต์/ผู้ใช้จากสภาพแวดล้อม ไม่ commit ไฟล์ที่มีรหัสผ่าน 

mysqldump --single-transaction --set-gtid-purged=OFF \
  -h <host> -P <port> -u <user> -p \
  --ssl-mode=REQUIRED \
  <database> \
  app_config badge_display_groups badge_rules \
  badge_rule_thresholds badge_rule_conditions \
  > badge-rules-backup-$(date +%Y%m%d-%H%M).sql

# ถ้าต้องการเก็บปูมคำนวณด้วย
mysqldump --single-transaction \
  -h <host> -P <port> -u <user> -p \
  --ssl-mode=REQUIRED \
  <database> badge_calculation_logs \
  > badge-calculation-logs-backup-$(date +%Y%m%d-%H%M).sql

จดควบคู่: Git SHA ของแอป, ไฟล์ seed ที่จะรัน (default หรือ prod), ค่า badge_rules_version ก่อนเปลี่ยน

สิ่งที่อยู่ในรีโป ใช้ย้อนฐานได้หรือไม่
scripts/db/seed-all-rules_backup.sql เป็น snapshot ของ generated SQL เก่า (รูป mock SVG) ไม่ใช่ dump ของ Azure ใช้ย้อน “ชุดกฎใน Git” ได้ถ้าตั้งใจกลับไปเวอร์ชันนั้น
scripts/db/uat_sony_table.sql dump อ้างอิง ณ วันที่ในไฟล์ ไม่รับประกันว่าตรงฐานปัจจุบัน
Git history ของ seed-data.mjs / prod/seed-data.mjs ย้อนโค้ดแล้วรัน db:seed / db:seed:prod ใหม่ จะเขียนทับกฎให้ตรงไฟล์นั้น

ย้อนกลับ (Rollback)

  1. หยุดการ seed ซ้ำถ้ายังไม่เสร็จ
  2. กู้จากไฟล์ dump ที่ถ่ายก่อนอัปเดต (restore เฉพาะตารางกฎ หรือทั้งฐานตามขอบเขตที่สำรอง)
  3. ทางเลือก: checkout ไฟล์ seed เวอร์ชันก่อน แล้ว npm run db:seed หรือ db:seed:prod — จะลบกฎที่เพิ่มในเวอร์ชันใหม่ถ้าไม่มีในไฟล์เก่า
  4. npm run db:verify ให้ตรงไฟล์ที่ใช้ย้อน
  5. ตรวจ badge_rules_version และเคสที่ยืนยันแล้ว (เช่น มี/ไม่มี product-sel1224gm) 
# ตัวอย่าง restore ตารางกฎ (ปรับตามเครื่องมือที่อนุญาต)
mysql --ssl-mode=REQUIRED -h <host> -P <port> -u <user> -p <database> \
  < badge-rules-backup-YYYYMMDD-HHMM.sql
ถ้า restore ทับตารางที่มี FK ให้ทำตามลำดับที่ dump กำหนด หรือปิดตรวจ FK ชั่วคราวเฉพาะหน้าต่าง restore ที่ควบคุมได้ อย่า seed ชุด default ทับ UAT ที่ต้องมี SEL1224GM เป็นเหรียญสินค้า

เมื่อ seed ล้มระหว่างรัน

seed.mjs เรียก beginTransaction และ rollback เมื่อ throw ฐานควรกลับไปสถานะก่อนคำสั่งนั้น จากนั้นแก้ข้อมูล seed หรือการเชื่อมต่อ แล้วยิงใหม่ ไม่ต้อง restore ถ้าธุรกรรมไม่ถูก commit

ไฟล์ SQL ที่ generate ใช้ START TRANSACTION / COMMIT การ import ที่ล้มครึ่งทางขึ้นกับไคลเอนต์ — ถ้าไม่แน่ใจให้ restore จาก dump

Schema rollback

migrate.mjs ไม่มี down migration คอลัมน์ที่เพิ่มแล้วจะไม่ถูกลบด้วยการรัน migrate ซ้ำ ถ้าต้องถอดคอลัมน์ ต้องมี ALTER ด้วยมือและแผนทดสอบแยก โดยทั่วไปการย้อนกฎไม่ต้องถอด schema
