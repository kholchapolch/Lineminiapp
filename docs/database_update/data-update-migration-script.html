Data Update Script / Migration Script

Script ที่ใช้ปรับปรุงข้อมูล พร้อม Version และวิธีใช้งาน

ไม่มีตาราง schema_migrations เวอร์ชันข้อมูลกฎอยู่ที่ app_config.badge_rules_version ค่าปัจจุบันใน seed ทั้งสองชุด: 2026-07-24-product-urls-001

เวอร์ชัน (Version)

ชั้น ที่เก็บ ค่าปัจจุบัน
Schema ลำดับ statement ใน scripts/db/migrate.mjs ไม่มีเลขเวอร์ชันในฐาน — รันซ้ำได้ (idempotent)
Badge rules scripts/db/seed-data.mjs และ scripts/db/prod/seed-data.mjs คีย์ badge_rules_version 2026-07-24-product-urls-001
สำเนา SQL เก่าในรีโป scripts/db/seed-all-rules_backup.sql 2026-07-20-confirmed-badge-rules-001 — ไม่ใช่แหล่งความจริง
เมื่อแก้กฎ ระดับ หรือเงื่อนไข ต้อง bump badge_rules_version ชุด default กับ prod ใช้สตริงเดียวกันทั้งที่แคตตาล็อกสินค้าต่างกันที่ SEL1224GM — อย่าใช้สตริงนี้แยกว่า seed ชุดไหนอยู่ในฐาน

รายการ script

คำสั่ง ไฟล์ สิ่งที่ทำ
npm run db:migrate scripts/db/migrate.mjs สร้างตาราง/คอลัมน์/index ALTER/INDEX ที่ซ้ำข้ามด้วย ER_DUP_FIELDNAME / ER_DUP_KEYNAME ไม่ลบแถว
npm run db:seed seed.mjs + seed-data.mjs ธุรกรรมเดียว: upsert app_config ลบแล้วใส่ badge_display_groups upsert กฎ แล้วแทนที่ thresholds/conditions ของกฎที่ seed ลบกฎที่ไม่อยู่ในไฟล์ (CASCADE ลูก)
npm run db:seed:prod seed.mjs --seed ./prod/seed-data.mjs เหมือน seed แต่ใช้ชุด UAT/prod (URL รูป blob, มีเหรียญ SEL1224GM)
npm run db:seed:all / :prod seed-all-rules.mjs migrate → seed → verify ติดกัน
npm run db:seed:sql generate-seed-sql.mjs เขียน seed-all-rules.sql จาก seed (ไม่แตะฐาน)
npm run db:seed:sql:prod generate + --out ./prod/seed-all-rules.sql สร้าง SQL ชุด prod — ไฟล์นี้ไม่ได้อยู่ในรีโปตอนจัดทำเอกสาร
npm run db:seed:sql:check generate-seed-sql.mjs --check CI บังคับให้ SQL ที่ commit ตรง seed เริ่มต้น
npm run db:verify / :prod verify.mjs เทียบ COUNT ตารางกับความยาวอาร์เรย์ใน seed และมีคีย์เวอร์ชัน
npm run db:reset reset.mjs DROP ตารางแอปทั้งหมดรวม badge_calculation_logs แล้ว migrate + seed ชุด default + verify — ใช้แค่ local
regenerate prod seed scripts/db/prod/generate-seed-data.mjs อ่าน dump uat_sony_table.sql ไม่รันใน CI

วิธีใช้งาน

ข้อกำหนด

  • DATABASE_URL รูปแบบ mysql://user:pass@host:port/db (ไม่มี secret ในเอกสารนี้)
  • Azure MySQL: DATABASE_SSL=true หรือ ?ssl=true — ไม่ปิดการตรวจใบรับรอง

Local — ใส่กฎชุด default

export DATABASE_URL='mysql://sony:sony@127.0.0.1:3307/sony_badges'
npm run db:migrate
npm run db:seed
npm run db:verify

หรือ npm run db:seed:all / ล้างทั้ง schema: npm run db:reset

อัปเดตกฎในโค้ดแล้วส่งเข้าฐาน

  1. แก้เฉพาะ scripts/db/seed-data.mjs (หรือ prod ตามสภาพแวดล้อม)
  2. bump badge_rules_version
  3. npm run db:seed:sql และ npm run db:seed:sql:check
  4. สำรองฐาน แล้ว npm run db:seed หรือ db:seed:prod
  5. npm run db:verify หรือ db:verify:prod

ทางเลือก SQL ด้วยมือ

npm run db:migrate
# แล้ว import scripts/db/seed-all-rules.sql (ชุด default)
npm run db:verify
Push แอปไป UAT ไม่รัน migrate/seed workflow ตรวจแค่ db:seed:sql:check กับเทส/lint/build ผู้ปฏิบัติการต้องรัน script ต่อ Azure MySQL จากโฮสต์ที่เข้าถึงได้
