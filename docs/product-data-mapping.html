Field mapping

Sony API → ฟิลด์ภายใน → การใช้
คำธุรกิจ Sony warranty ฟิลด์ในแอป กฎเหรียญใน DB
Product Model prodDetails[].modelName sku และ modelName (ค่าเดียวกันจาก warranty) เทียบกับรหัสรุ่นในกฎหลัง normalize (uppercase, trim, suffix) badge_rules.product_model_code และ badge_rule_conditions.sony_skus
Product Name ไม่มีฟิลด์ชื่อทางการตลาดใน warranty response ใช้ badge_rules.badge_name เป็นชื่อบน UI ใส่ตอน seed เช่น FE 24-70mm F2.8 GM II
Category ไม่มีหมวดจาก Sony API displayGroupCode ของกฎ เช่น prime-lens badge_rules.display_group_code ↔ badge_display_groups.group_code
Serial Number prodDetails[].serialNumber serialNumber ไม่เก็บในกฎ
วันลงทะเบียน prodDetails[].registrationDate registeredAt เทียบกับ registration_start / registration_end
วันหมดประกัน warrantyExpiryDate ไม่ map ไม่ใช้
Warranty ไม่มี SKU แยกจากชื่อรุ่น แอปจึงใช้ modelName เป็นรหัสเทียบ ค่าในกฎต้องเป็นรหัสรุ่นแกน เช่น SEL2470GM2 ไม่ใช่สตริงเต็มอย่าง SEL2470GM2/QSYX

ข้อมูลที่ใช้คำนวณ Badge

ฟิลด์ เหรียญผลิตภัณฑ์ เหรียญ Quest / Mission
Product Model (sku) ใช้ — ต้อง match sony_skus ของกฎนั้น (มักมีรุ่นเดียว) ใช้ — นับรุ่นที่อยู่ใน Eligible Product ของแต่ละ condition
Product Name ไม่ใช้คำนวณ ใช้แสดงชื่อ ไม่ใช้คำนวณ
Category ไม่ใช้คำนวณ ใช้จัดกลุ่มบน UI quest อยู่กลุ่ม quest
Serial Number ใช้ปลดล็อก ถ้ามีอย่างน้อยหนึ่งซีเรียลที่รุ่นตรง quantity = จำนวนซีเรียล ไม่ได้ใช้ซีเรียลเป็นรหัสเทียบ ไม่นับซ้ำต่อซีเรียล — นับรุ่นไม่ซ้ำ (unique SKU) ต่อเงื่อนไข
วันลงทะเบียน ต้องอยู่ในหน้าต่างลงทะเบียนของกฎ ถ้ากฎกำหนดไว้ (seed ปัจจุบันเป็น null = ไม่จำกัด) เช่นเดียวกันก่อนนับ matched count

กฎการเทียบรุ่น

  • uppercase + trim
  • เท่ากับรหัสในกฎ หรือขึ้นต้นด้วยรหัสนั้นแล้วส่วนที่เหลือเป็น suffix แคตตาล็อก เช่น /QSYX, SYX, QSYX
  • SEL70200GM ไม่ถือว่า match SEL70200G
ตัวอย่าง warranty → กฎ modelName: "SEL2470GM2/QSYX" → sku ภายในเป็นสตริงนั้น → match กฎ product-sel2470gm2 ที่ sony_skus: ["SEL2470GM2"]
ซีเรียลสองตัวรุ่นเดียวกัน เหรียญผลิตภัณฑ์: ปลดล็อก, quantity = 2, รายการ registrations สองแถว Quest: นับ 1 รุ่นในเงื่อนไขนั้น
