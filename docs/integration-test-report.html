Timeout

IT-16 · Sony fetch timeout

Not automated / no named timeout — LiveSonyProductsClient.getCustomerProducts เรียก fetch โดยไม่มี signal, ไม่มี deadline ในแอป

ผลที่คาดเมื่อแพลตฟอร์มตัดการเชื่อมต่อ:

  • ไม่มีรหัส TIMEOUT ใน { code, message }
  • ข้อผิดพลาดของ fetch จะถูกห่อเป็น error ทั่วไป แล้ว /api/customer-products คืน 500
  • /api/my-* ถ้าโหลดแคตตาล็อกล็อกได้ จะคืน HTTP 200 ที่ล็อกทั้งหมด ไม่โชว์ข้อความ timeout แยก
รอบนี้ไม่ได้จำลอง network hang กับ APIM จริง หากต้องการเคส UAT ควรกำหนด SLA (เช่น 5–10 วินาที) ที่ gateway แล้วบันทึกสถานะ HTTP

API Error

IT-17 · HTTP ที่ไม่ใช่ 200 และไม่ใช่ 404

Specified, not automated — โยน SonyProductApiError (code: SONY_PRODUCT_API_ERROR, safeMessage: Badge data is temporarily unavailable.) รวม 401/403 จากคีย์ผิด, 5xx จาก APIM, และ payload ที่ parse ไม่ได้หลัง HTTP 200

IT-18 · ไม่มี subscription key ในโหมด live

Pass (config) — loadAppConfig โยนเมื่อ SONY_PRODUCT_API_MODE=live แต่ไม่มี SONY_PRODUCT_API_SUBSCRIPTION_KEY แอปไม่ควรบูตในสถานะนี้บน UAT/production

IT-19 · เซสชันไม่ผ่าน (ไม่ใช่ Sony แต่เป็น integration ชั้นหน้า)

Pass — /api/customer-products ไม่มีคุกกี้เซสชัน → HTTP 401 UNAUTHORIZED รวมกรณีส่ง ?lineuuid= โดยไม่มี debug mock

IT-20 · พฤติกรรมต่างกันตาม API ผิว

เมื่อ Sony ล้มเหลว (When Sony fails)
Endpoint HTTP Body
GET /api/customer-products 404 หรือ 500 { code, message } แบบปลอดภัย
GET /api/my-badges, /api/my-products, /api/my-missions 200 (ถ้าโหลดกฎได้) แคตตาล็อกล็อก · ไม่มีรหัส Sony ใน JSON

ช่องว่างและข้อเสนอ (Gaps)

  • เพิ่ม unit test โหมด live สำหรับ HTTP 404, 500, payload ไม่มี prodDetails, และแถวที่ขาด modelName
  • กำหนด timeout + AbortSignal แล้วทดสอบว่าถูก map เป็น SONY_PRODUCT_API_ERROR (หรือรหัสใหม่ที่ตกลงกับ Sony)
  • รันชุดเดียวกันกับ APIM UAT จริง (ไม่ใช่ mock fetch) สำหรับ lineId ที่ Sony จัดให้: มีสินค้า, ไม่มีสินค้า, ไม่มีโปรไฟล์
  • ตัดสินใจว่า my-* ควรส่ง error JSON เหมือน customer-products หรือคง locked catalog
